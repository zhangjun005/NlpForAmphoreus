# 05 · 归一与清洗：v2 语料（不改原文，只加字段）

## 1. 目标与意图

v1 语料（24,206 条）已经「结构干净」，但直接用于分析仍有三个障碍：

1. **说话人未归一**：`speaker` 是 505 个原样标签，`小三月`/`长夜月`/`三月七` 是三个人还是同一个人？
   `「冬霖爵」塞涅卡` 与 `塞涅卡` 算不算同一个？——不解决，角色级统计全错。
2. **文本有脏点**：`他/她` 性别占位符、`*强调*` 星号、模板残留 `}}`、整句 `*动作描写*` 被误标成对白。
3. **主/额外对话混在一起**：`{{折叠}}` 里的可选闲聊（1,459 条）会污染时序与情感分析。

本阶段目标是产出 **v2 语料**：在**绝对不改 `text` 原文**的前提下，给每条记录补 4 个派生字段，
并把「归一 + 清洗」的规则、统计、示例全部文档化、可重跑（`tools/normalize-corpus.js` 幂等）。

## 2. 方案

### 2.1 原则：只加字段，不覆盖原文

| 原则 | 含义 | 好处 |
|---|---|---|
| `text` 永不改写 | 原文完整保留 | 任何清洗口径都可回溯；下游想用原文随时可用 |
| 清洗结果另存 | `text_clean` | 同一句可以有「原文版/清洗版」两种视图 |
| 归一结果另存 | `canonical_speaker` + `form` | 未命中的原文 `speaker` 仍保留，不猜不丢 |
| 视图软切分 | `view=main/extra` | 不物理拆文件，下游自行 `filter` |

### 2.2 归一方案

严格按配置的 6 级优先级执行（`data/config/speaker-alias.json` 的 `normalization_order`）：

1. `speaker_literal_map` 精确命中（最高优先级，人工确认过的原样字符串）；
2. `canonical.speaker_aliases` 精确命中；
3. 按 `title_prefix_patterns` 剥前缀（`「X爵」`、`「…」`、`『…』`）后重试 1–2；
4. 剥成对 `「」『』`、去尾部括号注音后重试；
5. `form_map` 命中（形态 → 角色 + form）；
6. 仍未命中 → `canonical=null`，保留原文，进人工确认清单。

补充约定：先对**原始写法**跑 1→2→5，再对「剥前缀/去引号/去括号」的写法跑同一顺序（优先级高于写法宽容度）；
`non_speaker_labels` 一律 null；`meme_terms` 命中即 null；`known_conflicts` 六条全部遵守；未命中不猜。

### 2.3 清洗方案（6 类）

| 类别 | 规则 | 说明 |
|---|---|---|
| `template_residue` | 先删成对 `{{…}}`，再删被截断的 `{{…` | 修复 216 条模板残留 |
| `html_br` | 删 `<br>` / `<br/>` / `<br />` | 本批语料 0 条（防御性保留） |
| `wiki_link` | `[[目标\|显示]]`→显示、`[[目标]]`→目标 | 本批 0 条 |
| `he_she` | `他/她` → `开拓者` | 116 处替换，保留 1 处复数例外 |
| `emphasis_star` | 行内 `*强调*` 去星号、保留词义 | 684 个星号（342 对） |
| `stage_direction` | 整句被一对 `*` 包住且无对话标点 → `kind=narration` | 19 条改判（唯一会改 `kind` 的规则） |

### 3.3 清洗统计

累计被清洗记录 **623 条（2.57%）**：`template_residue` 216 / `html_br` 0 / `wiki_link` 0 /
`he_she` **109 条（116 处）** / `emphasis_star` **280 条（684 个星号）** / `stage_direction` 19 条。

- `he_she`：BWiki 为兼容双主角写作 `他/她`；唯一例外是 3.6#07 长夜月台词里的「他/她们俩」，
  指代对象待人工确认，**保留 1 处不替换**（109 + 1 = 110 条记录 / 116 + 1 = 117 处）。
- `emphasis_star`：342 对 `*…*` 中，19 对是整句舞台指示（转 `kind=narration`，见上），
  其余 280 条记录去星号保留词义（如 `*我们*` 是缇宝指代分身群体，**不能删**）。
- `stage_direction`：19 条（如 `*泰坦悲伤的低鸣*`、`*低吼*`）改判 `narration`；
  另有 11 条「整句被 `*` 包住但含对话标点」是角色演戏/模仿时的整段台词，**保留为 dialogue、只去星号**。
- 清洗后 `text_clean` 为空 **10 条**：原文只剩被截断的模板（如 `{{颜色`），语义在 v1 解析阶段已丢失；
  人读版对这 10 条回退原文。
- 唯一会改 `kind` 的规则就是 `stage_direction`：v2 的 kind 变为 dialogue 20,672 / option 2,399 / narration 1,135。

### 3.4 去重（检测在 v2，标记在 final）

- v2 阶段只做**检测与报告**（`data/reports/qa-checks.md`）：按 `(task, kind, speaker, text)` 判重，
  v1 有 **495 组 / 冗余 901 条（3.72%）**，来自同一句台词在多个分支/多次对话中重复出现，**不是抓取重复**；
- v2 语料**不删行**（保 id 连续、保原文可比）；
- 去重**标记字段**直到 final 才落地：`is_duplicate` + `dedup_group`，共标 **1,120 条 / 626 组**
  （final 口径含 v3.1 新增记录，唯一 25,212 条）。差 901 → 1,120 的原因是语料从 v1 换成 v3.1，见 `06`。

## 5. 决策与取舍

| 决策 | 取舍 | 理由 |
|---|---|---|
| **不改 `text`**，清洗写 `text_clean` | 放弃「就地清洗省字段」 | 原文是唯一事实源；任何清洗口径都可回溯/对比 |
| 未命中 `canonical=null` 不猜 | 放弃「覆盖率好看」 | 错并 > 漏并；漏的还能进人工清单，错的会污染全部下游 |
| `extra` 不物理拆文件 | 放弃「两个文件更直观」 | 物理拆分会让 id 连续性、跨视图关联变复杂；`view` 软切足够 |
| `kind` 只允许舞台指示改判 | 放弃「顺手修正其他可疑 kind」 | 基线要稳定；其他可疑类型（括号动作描写 376 条）留给分析层过滤 |
| 去重只标记不删除 | 放弃「产出干净唯一句集」 | 分支台词重复是剧情结构的一部分；删了会破坏「阅读顺序」语义 |
| 配置缺漏只写建议不改配置 | 放弃「脚本自动补 alias」 | 配置是人工资产，自动补会把错误固化；扩表必须走人工评审（见 `04`） |

## 6. 踩过的坑与修正

1. **10 条 option 清洗后为空**：`{{颜色` 这类被截断的模板，字符串清洗无法恢复语义
   （v1 在解析阶段就丢了正文）。修正：不掩盖——文档里单列这 10 条，并把根因交给 v3.1 解析器修复
   （v3.1 改「先展开模板再解析」后 `{{`/`}}` 残留归零）。
2. **模板残留分两类，只有一类能清洗**：20 条是「文本在 `{{` 处被截断」（会丢文本，**必须修解析器**），
   196 条是「尾部多出 `}}`」（可字符串清洗）。修正：QA 报告明确区分，防止只做清洗就以为修好了。
3. **`他/她` 的数字口径**：`data/README.md` 早期写「153 处」，实测是 **117 处 / 110 条记录**；
   v2 实际替换 116 处（保留「他/她们俩」1 处）。修正：QA 报告按实测给出 110/117，README 标注差异。
4. **`*强调*` 的数字口径**：README 早期写「282 处」，实测 **342 对 / 299 条记录**（其中 `*我们*` 273 处）。
   v2 去星号覆盖 684 个（=342 对），与 299 条的差额来自 19 条整句舞台指示（改判 kind，单独处理）。修正：口径写清。
5. **清洗后「空文本」不能悄悄丢**：有 10 条 `text_clean` 为空。修正：人读版回退原文，文档单列清单；
   final 阶段实测空 `text_clean` 为 0（v3.1 修好模板后不再产生空文本）。
6. **归一引擎两套口径**：`normalize-corpus.js`（含 canonical 键兜底）报「435 个写法 / 4,032 条未匹配」，
   `report-corpus.js`（严格只跑规则 1–5）报「434 个 / 4,043 条」。两个数都对但**不可混用**。
   修正：`speaker-alias-changes.md` §0 专门说明差异来源，报告引用时必须标口径。
7. **v2 继承了 v1 的解析缺陷**：v2 是在 v1 语料上做的，所以 v1 丢掉的 `:` 旁白、短信、内嵌说话人
   在 v2 里同样没有——清洗做得再干净也补不回来。修正：这一认识直接推动了 v3.1 解析补全
   （24,206 → 26,332），以及 final 重新做归一/清洗（而非在 v2 上打补丁）。
8. **`step_title` 里的 `他/她` 没洗**：全篇 1 个步骤标题含 `他/她`（`找到开拓者并带他/她回家`），
   影响 43 条记录的 `step_title` 字段。修正：本轮只按任务要求清洗 `text`；如需统一，可对 `step_title`
   复用同一规则（记为遗留项）。
