# 02 · 抓取阶段：索引、wikitext 缓存与剧情顺序

## 1. 目标与意图

阶段 01 选定 BWiki 后，本阶段要交付**可离线重建的原始数据底座**，具体要求：

1. 拿到 3.0–3.7 全部主线的**任务页清单**（不能漏页、不能混入活动/支线）；
2. 把每个任务页的**原始 wikitext** 落盘成缓存，保证后续解析迭代可反复重跑、不再依赖网络；
3. 确定 67 个任务页的**真实剧情顺序**（页面在 wiki 上的书写顺序 ≠ 剧情顺序）；
4. 用浏览器渲染做一次**人工核对**，确认解析出的台词确实出现在页面上。

## 2. 方案：三件事各有哪些做法

### 2.1 任务索引

| 做法 | 问题 | 结论 |
|---|---|---|
| 解析「开拓任务」列表页 HTML | 正文是 SMW `#ask` 服务端渲染，无 `table/tr` | ❌ 不可行 |
| 解析同页 wikitext | 只有 7 个章节标题 + 查询语句，无条目 | ❌ 不可行 |
| **SMW `action=ask` 查询** | — | ✅ 采用（74 页） |
| 用 SMW 结果 + 章节卡片交叉核对 | 有 1 页不在分类组合里 | ✅ 采用（补漏后 75 页） |

### 2.2 正文获取

| 做法 | 问题 | 结论 |
|---|---|---|
| 抓渲染后 HTML 的文本 | 模板/折叠结构被拍平，只能拿到"可见文本"，拿不到说话人与折叠标记 | ❌ 不可行 |
| **`action=parse&prop=wikitext`** | — | ✅ 采用，逐页缓存 |
| Playwright 渲染后取 `innerText` | 结构信息丢失、重、且需本机 Chromium | 仅用于**核对**，不作数据源 |

### 2.3 剧情顺序

| 做法 | 问题 | 结论 |
|---|---|---|
| 依 wiki 页面书写/返回顺序 | SMW 返回的是字母序，实测语料顺序成了「书、争、仇、公…」 | ❌ 不可行 |
| 依版本 + 系列编号排序 | 同一系列内编号可解释大部分顺序，但分支页/跨系列衔接会错 | 仅作兜底 |
| **前置任务/后续任务建链 + 拓扑排序** | 页面自带链字段，可还原真实前置关系 | ✅ 采用 |

## 3. 实施

### 3.1 SMW 取索引（`tools/ask-smw.js`）

查询语句（改范围时只改这里）：

```
[[分类:开拓任务]][[任务地区::翁法罗斯]]|?系列任务名|?任务编号|?所属版本|?任务类型|limit=500
```

- 结果写入 `data/raw/amphoreus-quest-index.json`（实测 8,935 B）：**74 个任务页**。
- 交叉核对：从列表页「第四幕•翁法罗斯」章节卡片解析出的链接（`tools/audit-section.js`）
  与 SMW 结果对比，发现 **1 页**「魔女的镜中回天」不在 SMW 分类组合里——它剧情发生在黑塔空间站，
  但归属 3.2 系列。补漏后索引共 **75 页**。
- 75 页里有 **8 页是「系列任务」汇总页（无正文）**：落木逐火英雄纪、门扉之启，王座之终、
  走过安眠地的花丛、在黎明升起时坠落、因为太阳将要毁伤、英雄未死之前、于长夜重返大地、成为昨日的明天。
  解析时跳过 → **有效任务页 67 个**。

### 3.2 wikitext 抓取与缓存（`tools/crawl-amphoreus.js`）

- 接口：`action=parse&format=json&formatversion=2&prop=wikitext&page=<页名>`；
- 缓存路径：`data/raw/wt-cache/<encodeURIComponent(页名)>.txt`，文件名是 URL 编码，`decodeURIComponent` 还原；
- 实测缓存：**75 个文件 / 2.48 MB**（这是 `wt-cache/` 的唯一依赖，也是离线重建的唯一输入）；
- 礼节：UA 用 Chrome 140；**180ms/页**、不并发；失败重试 3 次、指数退避（800ms × 尝试次数）；
  `missingtitle` 直接放弃不重试；超时 25–40s；
- 命中缓存则跳过，可安全重跑（只补齐缺的页）。

### 3.3 剧情顺序（拓扑排序）

解析每个任务页自带的 `前置任务` / `后续任务` 字段建链：

1. 先用 `cleanLink` 清洗链接（v3 起会剥掉字段前的 `*` 星号，否则标题匹配不上，链只能串到 1 页）；
2. 建图后做**拓扑排序**；同层无法区分时用 `(版本, 任务编号)` 兜底；
3. 校验：**有效 next 边 64 条**；边方向一致性违例 0；版本号严格单调 3.0 → 3.7；
4. 产物 `data/corpus/quest-order.json`（实测 25,183 B，67 条）：`order/task/version/series/series_no/prev/next/cast/region`。

各版本任务页数（实测）：3.0 共 10、3.1 共 9、3.2 共 10、3.3 共 9、3.4 共 6、3.5 共 7、3.6 共 9、3.7 共 7。

### 3.4 Playwright 渲染核对

- 探针：`tools/pw-test-launch.js`、`pw-test-cdp.js`（排查本机浏览器启动/沙箱问题）；
- 截图：`tools/pw-shot-bwiki.js`、`pw-shot-small.js`；
  产物 `data/shots/qa-index.jpg`（115,714 B）、`qa-quest.jpg`（64,471 B）用于直接预览；
  `kaituo-renwu.png`（3,744,836 B ≈3.7 MB）、`yinnian.png`（4,400,761 B ≈4.4 MB）是全页截图（高度 > 8192px，读图工具打不开，仅供人工查看）；
- 渲染文本：`kaituo-renwu.rendered.txt`（5,684 B）、`yinnian.rendered.txt`（52,744 B，848 行可见文本）；
- 初版核对结论（`data/README.md`）：抽检 41 条台词，28 条在渲染文本中命中，
  未命中的 13 条全部位于 `{{折叠}}` 块内（默认折叠 → `innerText` 不含）。
  ⚠️ 该结论后来被 QA 阶段推翻/修正：非折叠记录也有约 1/7 未命中，见 `06`。

## 5. 决策与取舍

| 决策 | 取舍 | 理由 |
|---|---|---|
| 以 **wikitext 缓存**为唯一正文源 | 放弃 HTML / 渲染文本 | 只有 wikitext 保留说话人模板、折叠、选项等结构 |
| 缓存**不入 git** | 放弃「克隆即用」 | 体积 + 版权限制；只保留脚本，任何人可重抓 |
| 页面区分「汇总页 / 正文页」 | 放弃「按索引全解析」 | 8 个系列汇总页无正文，硬解析会产出空/脏记录 |
| 顺序用**拓扑排序** | 放弃「按编号直接排」「按 wiki 顺序」 | 编号只在系列内有效；wiki 顺序是 SMW 字母序 |
| 同层用 (版本, 编号) 兜底 | 接受「同层顺序可能不完全等于玩家实际路径」 | 分支页本身没有唯一顺序，见下节坑 4 |
| Playwright 只做核对 | 放弃「用渲染文本当语料」 | 渲染文本丢失说话人/折叠/选项结构，且依赖本机 Chromium |

## 6. 踩过的坑与修正

1. **SMW 返回字母序，语料顺序全错**。v1 直接按 SMW 返回顺序抓，结果语料开头是「书卷啊…、争辩啊…、仇雠啊…、公民啊…」，
   与剧情无关。修正：改用「前置/后续任务」链做拓扑排序（v2 起），`order` 才与剧情一致。
2. **前置/后续字段带 `*[[标题]]` 前缀，链只串到 1 页**。字段值形如 `*[[远客啊，请聆听此世祈祷]]`，
   直接拿标题匹配会全部落空。修正：v3 起先剥 `*`、再取 `[[…]]` 内文本；有效边从个位数恢复到 **64 条**。
3. **`#` 小节锚点污染链接**。3 条 `next`、2 条 `prev` 带 `#小节名`（如 `英雄啊，兑现那染血的冀望#完成「再创世」`），
   `cleanLink` 只取 `[[…]]` 不剥 `#`，导致指向错误页面。修正：比较时忽略 `#` 后内容；
   该问题在 `quest-order.json` 中仍以原样保留，**下游不要把 `prev/next` 直接当相邻页用**。
4. **链有断点/反向边**：3.7 末页 `next` 指向范围外任务「幻月是慈悲的女王」；
   3.4 的「英雄啊，兑现那染血的冀望」「英雄啊，粉碎那悲哀的造像」是分支页，存在「后置指向更早页」的结构。
   修正：不强行修复数据，改为**口径说明**——「链一致性违例 0」只代表**边方向**一致；
   用「简单相邻链」口径会看到 8 处不吻合、2 条反向边（详见 `data/reports/qa-checks.md` §1.2）。
5. **`ask-smw.js` 有隐藏前置依赖**：脚本第 17 行直接 `readFileSync(data/raw/wt-银辇…txt)` 打印样例，
   删了这个抽样文件会 ENOENT 崩溃。修正：文档中把它列为前置条件（`docs/handoff.md` §6.4）。
6. **会覆盖产物的旧脚本**：`crawl-amphoreus.js` 不止写缓存，**还会用有 bug 的 v1 逻辑覆盖 `data/corpus/`**。
   修正：实践中「补缓存 → 立刻用 `build-corpus-v3.js` 覆盖回来」，并在文档里把这条列为高风险操作（§7.2-G）。
7. **Playwright 不可移植**：`pw-*.js` 硬编码了本机 `playwright-core` 与 Chromium 路径，
   换机要改路径；因此它们被明确排除在语料管线之外。
8. **全页截图太大无法预览**：`kaituo-renwu.png` / `yinnian.png` 高度超 8192px，读图工具打不开。
   修正：另生成小视口 `qa-*.jpg` 供预览，大图只留档。
9. **抓取太急可能被站点拦**：初期考虑并发抓 75 页，评估后放弃，统一为 180ms/页串行 + 重试退避。
