# 03 · 解析器 4 代迭代：从 wikitext 到 24,206 → 26,332 条记录

## 1. 目标与意图

把 `data/raw/wt-cache/` 里的 75 份 MediaWiki wikitext（纯文本标记语言）变成
**一行一条记录**的结构化语料：每条记录带任务、版本、系列、步骤、说话人、台词、类型（对白/选项/旁白）、
是否折叠块等字段，且**全篇按真实剧情顺序**排列。

难点在于 wikitext 是给渲染器看的，不是给 NLP 用的：

- 剧情正文与模板参数混在一起（`{{角色对话|…}}`、`{{剧情选项|…}}`、`{{任务描述|…}}`、`{{折叠|…}}`）；
- 章节层级用 `==` / `===` / `====` 表示，而剧情步骤恰好在三级标题；
- 同一段文本的写法不统一：`*角色：台词`、`{{角色对话}}` 气泡、`:` 开头的场景旁白、短信模板、内联对白；
- 页面本身的顺序不可靠，需要单独确定剧情顺序。

因此解析器不可能一次写对：本阶段实际经历了 **4 代**（v1 → v2 → v3 → v3.1），每代都留下文件供对照。

## 2. 方案：解析路线怎么选

| 方案 | 说明 | 问题 | 结论 |
|---|---|---|---|
| 装 MediaWiki 解析器（如 mwparserfromhell / PHP parser） | 完整实现 wikitext 语法 | 引入 Python/PHP 依赖；本项目坚持「Node 内置模块 + 0 依赖」，换机可跑 | ❌ 放弃 |
| 先渲染成 HTML 再抽文本 | 拿到的是渲染结果 | 丢失说话人模板、折叠块、选项块结构 | ❌ 放弃 |
| **纯本地正则 + 平衡括号内联展开** | 自己实现「当前 wiki 只用到的那部分语法」 | 需要逐代补洞，但完全可控、可复现、可离线 | ✅ 采用 |

配套的工程原则：

1. **先整块剥掉元数据再解析**：`{{任务}}`、`{{系列任务}}` 里也有清单式内容，不先剥会被当成旁白；
2. **逐行状态机**：按行识别标题层级与行型，避免跨行正则误配（v1/v3 的伪说话人就是这么来的）；
3. **模板展开要「平衡括号」**：`{{颜色|x|Y}}`、`{{注音|A|B}}`、`{{黑幕|x}}`、`{{图标|分类|显示}}` 各有取值口径；
4. **基线不破坏**：v1 定稿后，后续修复一律**新增文件**（v2 / v3.1 / final），并用 `v1_id` 回接。

## 3. 实施：四代迭代

### 3.1 v1 —— `tools/crawl-amphoreus.js`（抓取 + 解析一体）

- 输入 74 页索引，输出 `{task, series, version, step, idx, speaker, text, kind}`。
- 三个致命 bug：
  1. **顺序错**：直接按 SMW 返回顺序（字母序）抓，语料顺序成了「书卷啊…、争辩啊…、仇雠啊…、公民啊…」；
  2. **step 全错**：闭包变量 bug，所有记录的 `step_title` 都是「步骤1」；
  3. **模板截断**：`{{…}}` 只做浅层替换，正文在 `{{` 处被切断（`我{{黑幕`、`{{颜色`）。
- 处置：**不修复、不删除**，保留为反例；文件头明确标注「有 bug，保留供对照」（`data/README.md` §四）。

### 3.2 v2 —— `tools/build-corpus-v2.js`（只修顺序与字段）

- 修顺序：用 `前置任务/后续任务` 建链 + `(版本, 任务编号)` 兜底；
- 补字段：`location`（`{{任务描述}}` 里的地点）、`extra`（是否在 `{{折叠}}` 里）；
- 声称修了 step（每节标题单独记录 `step_title/step_idx`），但**章节切分只认 `==`（二级）**，
  而剧情步骤是 `===`（三级）→ 整页被当成 1 节，**step 实际仍错**；
- 前置/后续字段带 `*[[标题]]` 前缀星号的问题没处理，链只串到 1 页，顺序修复也不彻底。
- 处置：保留对照，不作为基线。

### 3.3 v3 —— `tools/build-corpus-v3.js`（第一代可用基线）

相对 v2 修两处关键问题：

1. **章节切分**：改为**逐行扫描**标题，同时记录 `chapter`（二级）与 `step_title/step_idx`（三级及以下）；
2. **剧情链**：先剥 `*` 与多余链接再建链，再做拓扑排序（同层用版本+编号兜底）。

解析规则（按行型分支）：

- `{{任务}}` / `{{系列任务}}`：整块剥除（元数据区）；
- `== 标题 ==` → `chapter`；`=== 标题 ===` → `step_title` / `step_idx`；
- `{{角色对话|模板开始|场景名}}` … 气泡对白：`kind=dialogue`，记录 `scene`；
- `{{剧情选项}}`：`|选项N=` → `kind=option`，`|剧情N=` 分支台词也保留；
- `{{任务描述}}`：地点旁白 → `location`；
- `*角色：台词`：常规对白；
- 其余 `*` 开头行：旁白 `kind=narration`；
- `{{折叠}}` 块内：`extra=true`（额外对话/可选闲聊）。

**v3 基线的实测数字**（`amphoreus.jsonl`，`data/reports/corpus-stats.md`）：

| 指标 | 数值 |
|---|---|
| 记录数 / 字数 | **24,206 / 528,626** |
| kind | dialogue 20,691 / option 2,399 / narration 1,116 |
| extra=true | 1,459 |

## 5. 决策与取舍

| 决策 | 取舍 | 理由 |
|---|---|---|
| 不引入 MediaWiki 解析器 | 放弃「语法完备」 | 0 依赖、换机可跑；本项目只需覆盖 wiki 实际用到的子集 |
| v3 基线 24,206 条**冻结**，修复走新文件 | 放弃「就地改 v1」 | 让每代产物可对照、可回滚；下游有稳定基线 |
| v3.1 **不删除** v1 记录、只追加修正 | 放弃「重写整条管线」 | 用 `v1_id` 100% 回接，保证可比；也方便 QA 逐条核对 |
| 新增 `kind=sms` / `sms_option` | 放弃「把短信塞进 dialogue/option」 | 短信是**不同渠道**（非当面），后续分析需能单独过滤（已加 `channel` 字段） |
| 开场内容用「同页首个步骤标题」回填 | 放弃「留空」或「用章节名冒充」 | wiki 本身没给标题；显式标 `step_title_inferred=true`，需要严格口径的下游可 `filter(!step_title_inferred)` |
| 选项块内记录顺序沿用 v1（先选项、后分支内容） | 放弃「选项与分支交错排序」 | 保证 v1 记录相对顺序不变；分支归属目前没有 `option_idx` 字段（记为遗留） |
| 不解析 `<br>` 分段叙事、`{{提示}}` 系列模板 | 留给 v3.2 | 会再改基线，本轮先交付稳定版本；已量化缺口（见下节坑 6） |

## 6. 踩过的坑与修正

1. **闭包变量 bug → step 全是「步骤1」**：v1 把 `step_title` 写进循环外的变量，所有记录指向最后一节。
   修正：v2 起每行状态机即时写入；v3 逐行扫描标题彻底解决（不同 step_title 628 个）。
2. **`==` 与 `===` 混淆**：v2 只认二级标题，整页 1 节，step 全丢。
   修正：v3 同时识别 `==`/`===`/`====`，`chapter` 取二级、`step_*` 取三级及以下。
3. **`*[[标题]]` 让链断掉**：前置/后续字段带星号前缀，v2 的链只串到 1 页。
   修正：v3 先 `cleanLink` 再建链，有效边恢复到 64 条，版本 3.0→3.7 严格单调。
4. **`{{注音|A|B}}` 取错参数**：v1 取最后一个参数（注音 B），把「雅努斯」读成「门径之泰坦」、
   「尼卡多利」读成「纷争之泰坦」。修正：v3.1 注音取正文 A，共修正 **846** 条文本
   （如「门径之泰坦的祭司」→「雅努斯的祭司」）。
5. **跨行正则造出伪说话人**：`{{剧情选项}}` 块内正则用 `\s*` 连接，跨行吞掉下一行 `:` 旁白，
   产出 `speaker="？天啊，太可惜了。"`。修正：分隔符只允许空格/制表符、逐行解析 + 标签校验。
6. **`:` 行与短信块被整块丢弃**：v3 没有 `^:` 分支、没有 `{{短信选项}}` 分支，
   造成 1,963 行场景旁白与全部短信缺失（`3.0#01` 的「要跃迁了，对吧？」就不在 v3 语料里）。
   修正：v3.1 补齐，语料从 24,206 → 26,332，字数 +38,172。
7. **文本在 `{{` 处被截断，事后清洗救不回来**：10 条 option 只剩 `{{颜色`（v1 语义已丢）。
   修正：v3.1 改「先展开再解析」；并把「截断类必须修解析器、不能只做字符串清洗」写进 QA 问题清单。
8. **v3.1 仍未解决的 3 处缺口（已量化，留 v3.2）**：① 787 行（28 页）纯 `<br>` 分段叙事未抽取（约 +790 条）；
   ② `{{提示}}` 94 行 / `{{提示消息}}` 31 行 / `{{短信警告}}` 11 行未入库；
   ③ 6 处 HTML 注释 `<!-- … -->` 内的约 10 条 `*` 台词被当正常对白保留，需下游剔除或 v3.2 预剥离注释。
9. **翻译口径陷阱**：`{{黑幕|…}}` 取最后参数会让**剧透文本被展开**（19 处无标记），
   报告若引用需说明「这是 wiki 折叠内容，不一定在玩家首周目可见」。
