> NLP 方法不是一堆必须全部使用的算法，而是把“文字问题”转换成“可计算问题”的工具。

| 追踪谁引用神谕         | 引述检测、事件抽取、时间序列分析 | 规则 + 角色标签 + 剧情顺序  | 引用轨迹       |

下面按你的项目顺序说明。

一、语料工程对应“数据预处理和信息抽取”

你现在已经做好的内容，在 NLP 里属于：

- corpus construction：语料库构建；
- preprocessing：文本预处理；
- information extraction：信息抽取；
- entity normalization：实体归一化；
- metadata annotation：元数据标注。

比如这一条：

```
{
  "speaker": "昔涟(迷迷)",
  "canonical_speaker": "昔涟",
  "form": "迷迷",
  "version": "3.7",
  "text_clean": "我一直以为，自己是逐火之旅的讲述者。"
}
```

这里已经完成了几个 NLP 任务：

- 识别说话人；
- 把“昔涟”和“迷迷”归到同一个角色；
- 区分角色本体和形态；
- 给文本添加版本和剧情位置；
- 清理模板、标记和无关符号。

这一步不是简单的“准备工作”，它决定了后面能不能准确回答“谁在什么时候说了什么”。

二、神谕抽取对应“规则型信息抽取”

神谕库不需要一开始使用复杂模型。因为神谕有比较稳定的格式，人工设计规则反而更可靠。

例如可以通过：

- 固定句式；
- 引号；
- “汝将……”模式；
- 十二黄金裔的已知名单；
- 注音模板；
- 人工核对。

抽取结果可以变成：

```
{
  "oracle_id": "oracle_06",
  "text": "汝将收梢于花开时，一如终结诞下起始。",
  "holder": "昔涟",
  "titan": "德谬歌",
  "version": "3.7",
  "task": "魔女的孤诣课题"
}
```

这在 NLP 里叫结构化信息抽取。它的特点是：

- 输入是自然语言；
- 输出是字段和关系；
- 规则和人工标注可以比机器学习更可靠。

注音解码也可以看成一个小型关系抽取任务：

```
表面词：灰白的黎明
所指：开拓者
关系：隐喻指向
证据：注音
```

三、神谕和剧情匹配对应“信息检索”

这是最标准的 NLP 任务之一：给定一个查询，在大量文本中找最相关的片段。

你的查询是神谕，文档是剧情场景。

先做最简单的关键词基线：

```
神谕：黄金、沐浴、最后一次
场景：黄金浴池、最后一次、阿格莱雅
```

可以使用 TF-IDF。它的直觉是：

- 一个词在当前神谕里出现；
- 但在整部剧情里不常见；
- 那么这个词对匹配就比较有区分度。

BM25 是 TF-IDF 的改进版，搜索系统经常使用它。它会综合考虑：

- 词出现次数；
- 词在全文中的稀有程度；
- 文档长度；
- 查询词覆盖情况。

这一步输出的是一个排名：

```
神谕 A
  1. 3.7#03 场景 23590，得分 8.21
  2. 3.7#01 场景 23070，得分 6.94
  3. 3.4#07 场景 18220，得分 4.10
```

然后再加入句向量。

句向量方法会把一句话转换为一个数字向量：

```
神谕 A → [0.12, -0.08, 0.44, ...]
剧情片段 B → [0.15, -0.05, 0.41, ...]
```

两者可以用余弦相似度比较：

\[ \text{similarity}(x,y) = \frac{x\cdot y}{\|x\|\|y\|} \]

它适合处理这种情况：

```
神谕说“最后一次沐浴于黄金”
剧情写“阿格莱雅走进黄金浴池”
```

两段文字未必共享很多词，但语义上可能有关。

所以推荐顺序是：

```
关键词匹配
→ TF-IDF/BM25
→ 中文句向量
→ 人工核对
```

不要一开始就只使用句向量。因为你需要知道复杂方法究竟比简单方法好在哪里。

四、神谕引用对应“事件抽取 + 文本分类”

你要判断一条提到神谕的文本属于什么情况：

```
原文出现
旁白转述
别人解释
角色本人引用
角色主动认领
结局宣告
改写或反转
```

这在 NLP 里可以看成一个小型文本分类任务。

输入是一句台词，输出是类别：

```
输入：角色台词
输出：引用类型
```

最开始可以用规则：

- 是否包含神谕关键词；
- 是否由对应角色说出；
- 是否保留神谕原句；
- 是否出现“我”“我的”“我们”等自我认领表达；
- 是否位于兑现任务附近。

如果要使用机器学习，可以把每句话表示成特征：

```
角色是谁
版本是多少
距神谕原文有多少条记录
是否包含神谕词
是否包含第一人称
是否出现“命运”“注定”“神谕”等词
```

然后使用逻辑回归或朴素贝叶斯分类。

不过，这部分不一定需要追求高自动化。12 条神谕本来就是小样本，比较合理的做法是：

```
机器初筛 + 人工标注 + 统计引用轨迹
```

五、语体分析对应“文体计量和显著性检验”

你要比较：

```
神谕原文
普通对白
角色引用神谕的对白
```

每条文本可以提取一组特征：

```
平均句长
词汇数量
抽象名词比例
情态词比例
人称代词比例
“汝”的出现
排比或重复结构
感叹句和祈使句比例
```

例如一段文本可以被表示成：

```
[平均句长=18,
 抽象名词比例=0.32,
 情态词比例=0.11,
 第二人称比例=0.08,
 重复结构=1]
```

这样每个文本就从“句子”变成了一个“特征向量”。

接下来可以做：

- 均值比较；
- 箱线图；
- PCA 降维；
- 卡方检验；
- t 检验或 Mann–Whitney U 检验；
- 词频差异和关键词分析。

这里的目标不是证明某个角色“更文学”，而是观察：

> 角色引用神谕时，是否在词汇和句式上更接近神谕原文？

如果神谕中常见“将、终、汝”，而角色在引用时这些词的比例上升，就可以说存在语体靠拢的迹象。

六、叙事显著性对应“片段排序和事件检测”

你现在的叙事显著性问题，本质上不是普通情感分类，而是：

> 给剧情片段排序，找出最可能发生叙事状态变化的片段。

所以它更接近 information retrieval 或 learning to rank，而不是单纯的二分类。

先把连续剧情切成片段：

```
一个步骤
一个场景
连续 5–10 条台词
一个旁白和后续对白组成的小段
```

然后每个片段提取特征。

普通基线特征：

```
死亡词数量
告别词数量
牺牲词数量
负面词数量
否定词数量
停顿符号数量
短句比例
第一人称比例
```

对应一个简单分数：

\[ S_{\text{base}} = w_1f_{\text{death}} +w_2f_{\text{farewell}} +w_3f_{\text{negative}} +w_4f_{\text{pause}} \]

优化版本加入结构特征：

```
当前片段和前后片段的语义距离
是否出现新角色身份
是否改变称呼或形态
是否从现在切到回忆
是否出现旧神谕或旧歌谣
是否回收了之前的重复母题
是否改变叙述者
后续是否持续出现新的剧情状态
```

于是：

\[ S_{\text{enhanced}} = S_{\text{base}} + \lambda_1f_{\text{semantic shift}} + \lambda_2f_{\text{identity change}} + \lambda_3f_{\text{motif return}} + \lambda_4f_{\text{state change}} \]

这里的“优化”不是一定要用深度学习，而是让模型观察更长的上下文。

昔涟诞生剧情之所以重要，就是因为：

```
普通基线：
死亡词少，告别词少，可能分数不高。

结构增强：
身份变化明显；
旧歌谣和记忆被回收；
讲述者/听众位置反转；
前文信息被重新解释；
后续剧情状态发生改变。
```

所以它的优化分数应该明显上升。

七、HMM 和知识图谱是什么性质的方法

HMM 是“序列状态模型”。

你的引用链可以表示成：

```
未出现
→ 被转述
→ 被解释
→ 被引用
→ 被认领
→ 被兑现
```

如果使用 HMM，就是让模型根据每段台词，推测它当前处于哪个状态。

知识图谱则是“关系组织方法”。

```
神谕 ——属于—— 黄金裔
神谕 ——包含—— 隐喻词
隐喻词 ——指向—— 事件
角色 ——引用—— 神谕
神谕 ——兑现于—— 场景
```

它更适合做查询、展示和组织结果，不一定是主要预测模型。

八、最终推荐的 NLP 技术链

最适合你当前项目的正式方法链是：

```
语料构建
→ 信息抽取
→ 实体归一化
→ 文本检索
→ 语义表示
→ 引述/事件分类
→ 文体特征分析
→ 时间序列统计
→ 叙事片段排序
→ 人工评测
```

具体对应为：

```
1. 规则和人工标注
2. TF-IDF / BM25
3. 句向量 + 余弦相似度
4. 词频和文体特征
5. 逻辑回归或简单排序模型
6. 可选 HMM
7. 可选知识图谱
```

你不需要同时使用 Word2Vec、BERT、HMM、LDA、WMD、图神经网络和知识图谱。更好的论文结构通常是：

```
简单基线
→ 加入更合理的语言特征
→ 加入跨上下文结构特征
→ 比较效果
→ 回到原文解释
```

这样你不仅能说“我用了 NLP”，还可以清楚地说：

> 只看词面时，模型主要找到显性死亡和告别；加入语义变化、身份变化和母题回收后，模型能够发现昔涟诞生这类词汇不强、但叙事意义很重的片段。

这就是一个完整、可解释、也符合课程要求的 NLP 项目。
