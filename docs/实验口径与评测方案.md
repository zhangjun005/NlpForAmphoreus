# 实验口径与评测方案（已拍板）

> 拍板时间：2026-10-24 ｜ 状态：**口径冻结，可以开始写数据准备与基线代码**
> 本文只记录"怎么做实验"的口径；研究动机与方向见 `方向与理由v2.md`，通俗解释见 `通俗思路.md`，方法对照见 `NLP思路.md`。

## 0. 拍板清单（不再反复改）

```text
候选单位：步骤实例 segment_id = version|task|step_idx
候选池：全部符合过滤规则的步骤实例（A、B 各自独立打分）
检测器 A：词面 + 局部情绪基线
检测器 B：A + 跨上下文结构特征
评测：同一候选池上的 Precision@k / Recall@k + 案例核对
权重：先验固定，标注集不用于调参；做敏感性分析
语体对比：全量结果 + 话题匹配结果（两组都报）
标注：规则先行 + 重测一致率（可选第二人 Kappa）
```

## 1. 候选单位：步骤实例

- **ID**：`segment_id = version + "|" + task + "|" + step_idx`
  - 不用 `step_title` 作 ID：同一个标题（如「剧情内容」）会跨任务重复；
  - `step_title` 只作显示名。
- **内容**：该步骤下的全部对白、旁白、选项记录。
- **两层粒度**：
  - 主评测：步骤实例（评 Precision@k / Recall@k）；
  - 细读与特征分析：步骤内的连续台词/句子（解释个案时用）。

## 2. 过滤规则：标记而非删除

| 规则 | 默认 | 处理方式 |
|---|---|---|
| `view` | 主实验只用 `main` | `extra`（折叠额外对话）不混入，但保留在语料里 |
| 选项文本 | 不删除 | 单独字段 `option_texts` + `has_option` 标记；主实验的文本身不混入 |
| 系统提示 / 战斗动作 | 不删除 | 用 `system_only`、`low_content` 标记；主实验排除，报告里给排除前后差异 |
| `step_title_inferred=true` | **纳入** | 标 `inferred=true`；敏感性分析里单独跑一版排除结果 |
| 空步骤 / 只有 1–2 条系统文本 | **不删除** | 标 `low_content=true`；主实验默认排除，但保留可追溯 |
| 单条系统文本 | 不删除 | 标 `system_like=true`（按句式启发式，见脚本） |

## 3. 候选池与指标

**A 与 B 都对同一批合格步骤独立打分**，不采用"A 粗筛 → B 重排"作为主口径（那会把 A 的漏检固化进 B 的上限）。

```text
合格候选池 = view=main 的步骤实例，排除 low_content
A：对候选池每个步骤打分 → 排序 → Top-k
B：对同一候选池每个步骤打分 → 排序 → Top-k
比较：A/B 的 Top10/20 重合度、Precision@10、Precision@20、Recall@20
```

检索类实验（神谕→事件）单独一套口径：12 条神谕为 query，候选为步骤实例，报 Recall@k / MRR。

## 4. 语体对比：全量 + 话题匹配

直接比"神谕 vs 对白"会被题材差异污染，因此**报两组**：

1. **全量比较**：展示整体差异（反映"文本整体差异"）；
2. **话题匹配比较**：在同一话题子集内比（神谕谈死亡/告别/命运的句子 ↔ 对白中谈同类话题的句子），尽量控制：
   - 句长（分箱匹配）；
   - 版本（同版本内配对）；
   - 任务阶段（按 `order` 分箱）；
   - 主题词（关键词命中）；
   - 是否由角色本人说出。

只有**匹配后差异仍然存在**，才下"语体差异"的结论。

## 5. 权重：先验固定 + 敏感性分析

不做"用 40–80 个标注片段调权重"。流程：

1. 事先确定特征清单；
2. 各特征标准化（z-score 或 min-max，按步骤实例内部）；
3. **事先固定权重**（初值如下）；
4. 标注集只用于评测，不参与调参；
5. 做敏感性分析。

**B 检测器初版权重**：

| 特征组 | 权重 |
|---|---|
| 普通词面/局部情绪 | 50% |
| 语义突变（与前后步骤的向量距离） | 20% |
| 身份变化（角色/形态/称呼/说话位置） | 15% |
| 母题回收（旧神谕/歌谣/重复台词在新语境出现） | 10% |
| 持续状态变化（后续步骤状态是否不可逆改变） | 5% |

**敏感性分析跑这几组**：

```text
W1 原始权重
W2 结构特征整体 +20%
W3 结构特征整体 −20%
W4 只留语义突变
W5 只留结构规则（去掉词面基线）
```

判定标准：不同权重下，昔涟诞生、神谕兑现、身份揭示等案例仍排前列 → 结论不依赖某组权重。

> 若将来真要学习权重：必须训练/测试分离；当前样本量（40–80）**不支持**，不推荐。

## 6. 标注方案（含一致性）

**流程**：
1. 写一页标注规则（0–3 级 + 7 类类型标签的定义与边界案例）；
2. 先标 10 个片段试标；
3. 隔几天、不看第一次结果，重新标同一批；
4. 比较两次一致率，对分歧案例改规则；
5. 规则固定后，再标正式 40–80 个片段；
6. 若有人协助：让其独立标 20 个片段，报告 Cohen's kappa。

**标注对象**：步骤实例（不是单句）。每个实例给：
- 显著性等级 `0/1/2/3`；
- 类型标签（可多选）：`identity / memory / prophecy / relationship / world / sacrifice / motif`。

## 7. 数据准备需要新增的字段（步骤实例表）

| 字段 | 含义 |
|---|---|
| `segment_id` | `version\|task\|step_idx` |
| `n_records` / `n_main` | 记录数 / main 视图记录数 |
| `n_dialogue` / `n_narration` / `n_option` / `n_sms` | 各类型计数 |
| `text_dialogue` / `text_narration` / `text_all` | 拼接文本（清洗后） |
| `char_len` / `char_len_dialogue` | 字符数 |
| `speakers` | 出现的 canonical 角色（去重） |
| `has_option` / `has_dialogue` / `system_only` / `low_content` / `inferred` | 标记位 |
| `pause_ratio` / `motif_count` / `ritual_count` / `structure_count` / `translation_count` | 重复功能统计（来自 `repeat_kind`） |
| `option_texts` | 选项文本（单独存放，不混入主文本） |

## 9. 实现细节：超长步骤的内部粒度（新增，2026-10-24）

**实测**（`data/corpus/segments.jsonl`，见 `tools/build-segments.js`）：

| 指标 | 数值 |
|---|---|
| 步骤实例总数 | **723** |
| 合格候选池（main、有对白、非 low_content） | **686**（94.88%） |
| 长度 P50 / P90 / P99 / max | **472 / 1,648 / 3,757 / 9,152** 字 |
| 规模分布 | 1–3 句 65 ／ 4–10 句 148 ／ 11–30 句 236 ／ **>30 句 237（34.5%）** |
| 含选项的步骤 | 348 |
| `step_title_inferred=true` | 40（5.53%） |
| low_content | 37 |
| system_only | 0（启发式偏严，实际由 low_content 兜住） |

**问题**：步骤实例长度极不均匀（最长 9,152 字 / 422 句）。以步骤为单位排序没问题，但"局部词面特征""语义突变"在超长步骤内部会被稀释。

**默认实现（属于"两层粒度"的落地，不改主单位、不额外标注）**：

- **评测与标注单位**：仍是步骤实例（`segment_id`）；
- **特征计算在步骤内部进行**：
  - 词面/情绪/停顿/短句类：按记录（句）计算后聚合（比例 + top-20% 均值）；
  - 语义突变：步骤内部按滑窗（20 条记录，步长 10）算相邻窗余弦距离，取 **max 与 mean** 作为该步骤的两个特征；
  - 身份变化/称呼变化：按步骤内首次出现位置检测；
  - 母题回收：步骤内 `repeat_kind ∈ {motif, catchphrase}` 命中计数。
- **聚合到步骤后**再进入 A/B 打分与排序。

**备选（仅在步骤级太粗时才启用）**：把 >30 句的步骤按旁白转折再切"子场景"，作为补充实验；主口径不变。

## 10. 实施顺序

1. ✅ 口径冻结（本文）
2. ⏳ 生成步骤实例表 `data/corpus/segments.jsonl` + 统计
3. ⏳ 12 条神谕表 + 隐喻解码表
4. ⏳ 人工标注（40–80 步骤实例）
5. ⏳ A 检测器（词面/情绪基线）
6. ⏳ B 检测器（结构增强）+ 敏感性分析
7. ⏳ 神谕—事件检索（关键词 → TF-IDF/BM25 → 句向量）
8. ⏳ 语体对比（全量 + 话题匹配）
9. ⏳ 案例核对与报告

> 每个环节的产出都要能回到原文核对；所有脚本放 `tools/`，语料与报告不入公开仓库。
