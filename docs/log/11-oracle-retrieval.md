# 11 · 神谕—事件检索（13 query × 686 document）

- **时间**：2026-10-24 17:45–18:05
- **目标**：检验「给定神谕，能否检索到它的兑现场景」，对比关键词 / TF-IDF / BM25 / LSA。

## 实际动作

1. 复用 agent `baseline-a`（task-12）实现 `tools/oracle_retrieval.py`：
   - query = 13 条神谕（原文 + `keywords`）；document = 686 个合格步骤（`text_all`）；
   - gold = `oracle-fulfillment.filled.json` 的 `fulfillment_segment`（13/13 在池内）；
   - 五种方法：关键词加权命中、TF-IDF(char 2–3gram)、TF-IDF(jieba 词)、BM25(k1=1.5,b=0.75)、LSA(词 TF-IDF + SVD100)；
   - 另做「注音隐喻扩展」变体（O09 的 汝→白厄 / 黎明→天外的救世主 / 灰白的黎明→开拓者）。
2. 产出 `data/config/oracle-retrieval-results.json`（122 KB，含每 query×方法 gold_rank/gold_score/Top3）与 `data/reports/oracle-retrieval.md`（32 KB）。

## 关键发现（必须先说）

- **12/13 条 gold 本身就是吟诵/引用该神谕的步骤**（gold ∈ occurrences），**10/13 条 gold 文本直接含神谕原文**；
- 因此对绝大多数神谕，测的是"能不能找到引用句"，不是"能不能找到语义兑现"；
- **唯一真正考验语义的是 O10**（反转兑现，gold 不引原文）：关键词排名 135 / TF-IDF(char) 7 / BM25 51；
- O10 还受**同词异序污染**：O11（『汝将于天地境界之海完成征服，长眠于涛声中』）与 O10 语序互换，所有方法的 Top1/Top2 都被 O11 的吟诵步占据——词面方法无法区分镜像对。

## 隐喻扩展

只有 O09 有注音隐喻：关键词方法 O09 排名 3→1、MRR 0.731→0.783；向量方法 ΔMRR≈0（扩展词是高频角色名，被 IDF 稀释）。13 条里只有 1 条能用，只能验证机制。

## 处置 / 下一步

- **gold 构造需要修**：建议下一轮做「query 掩蔽（去掉神谕字面）」或「候选池剔除含原文的吟诵步」的检索 v2，否则任何字面方法都会赢；
- 若要做语义检索，O10 这类"不引原文的兑现"才是有效测试样本；
