# 04 · 人类可读方法文档 + 注音语料

- **时间**：2026-10-23 23:26–23:39
- **目标**：把「从剧情原文到语料」的处理方法与依据写成**给人看**的文档（区别于给 AI 读的 `docs/stages/`）；并抽取注音对作为新资源。

## 实际动作

1. 新建 `docs/method/`，写 5 篇：
   - `README.md`：流程图 + 12 步速查表（每步：做法 / 关键依据 / 产出）；
   - `01-处理流程与依据.md`：主文档，每步含「原文样例 → 规则 → 凭什么」；
   - `02-踩坑与修正.md`：13 个真实错误的「现象/根因/证据/修法/教训」；
   - `03-注音语料.md`：1,020 对注音的结构与三个用途；
   - `04-重复台词判定案例集.md`：8 类重复（母题/口头禅/结构标记/翻译节点/仪式/停顿/分支转录/可重复交互）。
2. 写 `tools/collect-evidence.js`：从 wt-cache 抽全部 `{{注音|正文|注音}}` → `data/corpus/ruby-pairs.jsonl`（1,020 对 / 224 唯一 / 覆盖 64 页）。
3. 发现并记录：`{{注音|灰白的黎明|开拓者}}` 这类"预言藏名"只有白厄一条神谕具备；其余注音 90%+ 是「神名→神职」对照。
4. 写 `tools/analyze-duplicates.js`：把 1,126 条同任务重复拆成 `filler`（630 条冗余）vs 非 filler（496 条），并统计跨任务重复（104 组 / 跨版本 69 组）。

## 输入 / 输出

- 输入：`wt-cache/`、`amphoreus.final.jsonl`
- 输出：`docs/method/`（5 篇）、`data/corpus/ruby-pairs.jsonl`（259 KB）、`tools/collect-evidence.js`、`tools/analyze-duplicates.js`

## 验证

- 注音对数与页面覆盖用脚本复算；
- 重复分类的样例逐条回到原文核对（死刑/泰坦低语/时间开始流动/逐火…/明天见）。

## 问题与处置

- 最初把重复当"轮回证据"，读完原文后撤回（轮回写成同构句式，不是逐字重复）；
- 又一度把非 filler 重复归为噪声，被用户指出"死刑！死刑！是信息"后修正为 8 类功能分类。
