翁法罗斯（Amphoreus）的文本带有强烈的**希腊古典悲剧色彩、神权政治博弈以及充满宿命感的预言隐喻**。文本结构具有天然的“说话人元数据（Speaker Tag）”、“时序幕数（Act/Scene）”以及“神谕诗篇与现实对白交错”的特性。

围绕这一语料，可以设计以下 4 个兼具技术深度与叙事可解释性的 NLP 项目：

### 1. 悲剧神话中的“宿命-抗争”正交基底构建与角色心智轨迹追踪

- **切入视角**：翁法罗斯的主题深刻聚焦于“神谕预言（Destiny/Fatality）”与“凡人抉择（Free Will/Hubris）”的对立。传统情感分析只能粗暴地判定正负面，无法捕捉这种深层哲学张力。

- **核心语言分析方法**：

  - **自主构建词向量空间**：基于提取出的翁法罗斯全剧情文本，用 Gensim 训练专有的 Skip-gram 模型（`vector_size=128`, `window=5`）。

  - **正交语义轴（Semantic Subspace Projection）**：

    利用正反极性种子词集构造两个彼此正交的基底向量：

    - **宿命轴** $\vec{u}_{\text{命运}}$：由 `[定数, 预言, 枷锁, 诸神, 轮回]` 质心减去 `[打破, 抉择, 凡人, 叛逆, 变数]` 质心并归一化。
    - **理性/冷酷轴** $\vec{u}_{\text{秩序}}$：由 `[律法, 裁决, 牺牲, 永恒]` 减去 `[情感, 悲悯, 狂怒, 凡尘]` 并归一化。

  - **角色/章节标量投影**：

    遍历剧情各幕，提取特定角色（如阿格莱雅、卡斯托丽丝或开拓者）在不同章节下的全部发言台词，计算其句向量平均池化 $\vec{S}_{\text{role}, t}$，投影到双轴上：

    $$\text{Score}_{\text{命运}}(t) = \vec{S}_{\text{role}, t} \cdot \vec{u}_{\text{命运}}, \quad \text{Score}_{\text{秩序}}(t) = \vec{S}_{\text{role}, t} \cdot \vec{u}_{\text{秩序}}$$

- **展示效果**：

  - 输出角色的**二维性格/立场相空间演化轨迹图**（展示该角色随着剧情推进，是从顺从神谕逐渐滑向弑神抗争，还是走向冷酷秩序）。
  - 验证向量代数关系，测试 $\vec{v}_{\text{泰坦}} - \vec{v}_{\text{神圣}} + \vec{v}_{\text{凡人}}$ 在空间中最接近哪些词。

### 2. 泰坦神权与城邦同盟：基于多轮对话的动态社会拓扑与权力中心演化

- **切入视角**：翁法罗斯涉及城邦领袖、神职人员、异乡旅人与神秘势力之间的多方政治斡旋。通过非结构化台词，自动逆向出背后的政治派系与权力中枢变迁。
- **核心语言分析方法**：
  - **动态共现窗口切分**：不再使用生硬的全文滑动窗口，而是利用剧本自带的 `Turn`（轮次）和 `Scene`（场景），以同一场景内连续 3~5 句对话作为共现上下文。
  - **PPMI 加权图构建**：计算全剧情出场角色对之间的正点互信息（PPMI），剥离主角开拓者“逢人必聊”的全局高频噪声，提取真实的紧密关系网络。
  - **图论度量与社区发现**：
    - 采用 **Louvain / Leiden 算法** 自动挖掘派系（查看算法划分的社区是否准确还原城邦同盟、泰坦神侍等阵营）。
    - 逐幕计算角色的中介中心度（Betweenness Centrality）与 **PageRank**，量化谁是特定剧情阶段的“信息枢纽”或“幕后黑手”。
- **展示效果**：
  - 4~5 张随主线剧情推进而演变的角色关系拓扑网络图。
  - 关键人物的“话语权影响力指数”时序折线图，直观展现谁在关键转折点登顶权力中心。

### 3. 神谕预言（Oracle）与现实剧情的“跨文体语义对齐与伏笔解码器”

- **切入视角**：剧情中穿插了大量晦涩、古老且充满象征主义的神谕预言诗、石碑铭文；而在数幕之后，往往会发生具体的剧情事件与其呼应。

- **核心语言分析方法**：

  - **文本解构与文体切分**：将语料分为两组子集——《预言/神谕集》（短小、抽象、象征性词汇密集）与《现实剧情叙事/对话集》（具象动作、事件推进）。

  - **TF-IDF 加权与 Word Mover's Distance (WMD / 词移距离)**：

    - 由于预言诗通常使用隐喻（如用“落日”、“金枝”、“盲眼”指代具体角色的背叛或死亡），字面重合度极低，传统的 BLEU/ROUGE 无法匹配。

    - 使用基于词向量的 **WMD（词移距离）** 或 **Soft-Cosine 相似度**，在稠密语义空间中计算每一则神谕与主线各个核心事件段落的语义传输距离：

      $$\text{SoftCosine}(p, s) = \frac{\sum_{i,j} p_i s_j \cos(\vec{w}_i, \vec{w}_j)}{\sqrt{\sum_{i,j} p_i p_j \cos(\vec{w}_i, \vec{w}_j)} \sqrt{\sum_{i,j} s_i s_j \cos(\vec{w}_i, \vec{w}_j)}}$$

  - **伏笔跨度与隐喻热力矩阵**：计算全篇预言与主线事件的相似度矩阵，自动找出“该预言最可能对应第几幕的哪个重大转折”。

- **展示效果**：

  - 绘制 **预言-事件匹配热力图（Heatmap）**，高亮显示哪些具象情节跨越了数十万字精准落地了前期的神谕隐喻。

### 4. 希腊式城邦修辞学：角色说话风格指纹与身份分类器

- **切入视角**：神明/泰坦、哲人、平民、以及玩家所操纵的开拓者，在台词风格（语体严肃度、句式复杂度、词汇丰富度）上具有极其鲜明的反差。
- **核心语言分析方法**：
  - **词性分布（POS Tagging）与语言复杂度特征提取**：
    - 计算每个角色的 **TTR（Type-Token Ratio，词汇多样性）**。
    - 统计副词、成语、古汉语典故词的使用频率比例。
    - **句式长度均值与方差**（神明多用短促严厉的命令式或宏大冗长的排比式，平民多用口语短句）。
  - **TF-IDF 差异化特征词提取（Keyness Analysis）**：通过卡方检验（$\chi^2$）或对数似然比（LLR），提取每个角色相比全篇整体最具排他性的“风格指纹词”。
  - **无监督聚类与分类验证**：
    - 将角色风格向量（词性比例 + 复杂度指标 + Top 特征词向量）输入 PCA/t-SNE 降维聚类。
    - 训练轻量分类模型（如逻辑回归或朴素贝叶斯），测试仅凭一段匿名的台词，系统能否以 85%+ 的准确率逆向推断出这是哪位角色（或哪类阶层）的发言。
- **展示效果**：
  - 角色风格多维雷达图（涵盖“词汇丰富度”、“抽象概念占比”、“修辞密度”等维度）。
  - 台词匿名盲测混淆矩阵，验证哪些角色的语言风格最具有辨识度。

## 可以在哪里获得剧情文本？

要绕开解包仓库中复杂的任务树跳转（`NextActID`、条件分支节点以及 Hash Key 二次索引），最省力的方法是**直接抓取社区前端已经“拍平（Flatten）”好并组装完毕的二次数据源**。

以下是4个无需解析游戏底层对话树、能直接拿到线性文本的现成渠道与提取方案：

### 1. 抓取已解析数据库站点的 API（最推荐：直接拿到扁平化结构）我发现不太行

像 **Hakush.in** 或 **Yatta.top** 这类数据库站点，后端已经运行了树遍历算法，把复杂的任务跳转和文本哈希直接拼装成了顺序对话数组。前端渲染时请求的 JSON 极其纯净。

- **获取方式**：

  1. 浏览器打开 `hsr.hakush.in/quest` 或 `yatta.top/hsr/archive/story`。
  2. 定位到翁法罗斯（Amphoreus）对应的主线章节（如版本更新后的新开拓任务）。
  3. 按 `F12` 打开开发者工具，切到 **Network（网络）** 标签页，勾选 `Fetch/XHR`。
  4. 刷新或点击该任务，会看到一个针对该任务的单一数据请求（例如 `.../detail.json` 或 `api/quest/...`）。

- **数据结构特征**：

  返回的 JSON 已经把人物和对白线性化，格式类似于：

  JSON

  ```
  [
    {"speaker": "阿格莱雅", "text": "命运的织线早已在神龛前备好……"},
    {"speaker": "开拓者", "text": "我们什么时候出发？"}
  ]
  ```

  直接写几行 Python 脚本 `requests.get()` 批量拉取对应章节的任务 ID 即可，彻底避免处理跳转逻辑。

### 2. BWiki 剧情归档页批量爬取（适合单文本/TXT输出）（可以使用playwright试试）

B站星穹铁道 Wiki（BWiki）的维护组在版本更新后，会将剧情整理成纯粹的“说话人: 对话”排版，天然剥离了程序代码和复杂标签。

- **目标路径**：访问 BWiki 的 `剧情录制` 或 `开拓任务` 专栏，找到翁法罗斯对应的任务列表。

- **提取脚本（Python + BeautifulSoup）**：

  BWiki 的对话通常包裹在标准的 HTML 表格或特定 class 的 `div` 中，直接提取文本节点即可：

  Python

  ```
  import requests
  from bs4 import BeautifulSoup
  
  url = "https://wiki.biligame.com/sr/某个翁法罗斯任务页面"
  headers = {"User-Agent": "Mozilla/5.0"}
  resp = requests.get(url, headers=headers)
  soup = BeautifulSoup(resp.text, 'html.parser')
  
  dialogues = []
  # BWiki 的对话多集中在 .resp-tab-content 或特定 table
  for row in soup.find_all(['p', 'tr']):
      text = row.get_text(strip=True)
      if "：" in text or ":" in text:  # 说话人:台词 格式
          dialogues.append(text)
  
  with open("amphoreus_story.txt", "w", encoding="utf-8") as f:
      f.write("\n".join(dialogues))
  ```

### 3. 开源社区现成的“对话树拍平工具”（本地脚本一键转换）

如果你手头已经克隆了 `StarRailData`，无需自己从零写 DFS/BFS 去跑树跳转。GitHub 上有玩家针对米哈游解包仓库开源了专门的**剧情重构编译器**：

- **推荐工具**：

  - **`StarRail-Story-Parser`** / **`genshin-dialogue-dump` 系列衍生工具**：

    搜索这类社区工具，它们的核心功能就是输入 `TextMapCHS.json` 和 `QuestData.json`，自动执行拓扑排序并剪掉冗余分支，一键导出为按时间线排列的 `.md` 或 `.txt` 文件。

  - **处理机制**：工具内部内置了 `TalkSentenceConfig` 与 `Act` 节点的递归查找函数，直接调用命令：

    Bash

    ```
    python export_story.py --chapter "Amphoreus" --output "./output.txt"
    ```

### 4. B站视频字幕（Bilibili CC / AI 字幕）批量抓取

由于翁法罗斯主线通常有 6–10 小时以上的全流程视频，B站全流程剧情视频（如“原野上的愚者”等头部剧情 UP 主）的播放流中自带完整的官方 CC 字幕或高准确率 AI 字幕。

- **获取方式**：

  使用现成的字幕提取工具（如开源的 `bilibili-subtitle-download` 或油猴脚本“B站字幕下载”）。

- **底层接口原理**：

  直接请求 B站的字幕接口即可获取包含精确时间戳的纯对白流：

  ```
  GET https://api.bilibili.com/x/player/v2?cid={CID}&bvid={BVID}
  ```

  返回的 JSON 中 `subtitle.subtitles[0].subtitle_url` 即为完整的字幕 JSON 文件，遍历所有分 P 即可拼出按时间轴线性推进的纯剧本文本，且天然不带任何代码杂质。
