# 从剧情原文到语料：处理流程与依据

本文按**实际执行顺序**写。每一步都回答四个问题：**这一步在干什么 / 原文长什么样 / 我用了什么规则 / 凭什么说这个规则对**。

---

## 0. 先定范围：只做主线

**做什么**：只处理「开拓任务」3.0–3.7 的 67 个任务页，不碰活动、支线、散落文本。

**依据**（不是拍脑袋，是逐项排除）：
- 活动剧情以整活/番外为主，语体与主线不一致；
- 一个版本的活动，背景时间可能对应前几个版本的剧情（时间线会错位）；
- 支线大多与黄金裔主线无关；
- 散落文本（书籍/短信/道具文案）时间线更乱，混进来会污染"角色弧光"类分析。

**代价**：语料不含可选支线，所以"角色在支线里的表现"这份数据没有。这个取舍我记录在 `data/README.md` 的范围决策里。

---

## 1. 选数据源：BWiki 的 MediaWiki API + SMW

**做什么**：决定从哪里拿文本。

**依据**（四个渠道实测后被否）：

| 渠道 | 实测结果 | 否掉的原因 |
|---|---|---|
| hakush / yatta 类数据库 | 接口面是角色/光锥/遗器/数值 | 没有剧情对话接口 |
| B 站 CC 字幕 | 官方文档写未登录 `subtitles` 返回空数组 | 要 SESSDATA；且剧情视频挂的是解说字幕，不是台词 |
| Fandom 中文 wiki / 中文维基 | 本地 DNS 解析到非公网 IP，请求被拦 | 不可用 |
| 萌娘百科 | 页面能读，但 `action=parse` 返回 `action-notallowed` | API 被禁，只能整页抓，成本高 |

**留下的 BWiki** 有三样东西别的渠道没有：
1. `prop=wikitext` 拿得到**带说话人、选项、注音、折叠**的原始结构；
2. 装了 **Semantic MediaWiki**，任务索引可以按属性查（见下一步）；
3. 角色页有 `昵称/外号` 字段，把"谁怎么称呼谁"直接列出来了。

---

## 2. 任务索引：先发现「页面本身没有正文」

**做什么**：确定要抓哪些页。

**原文长什么样**（「开拓任务」页的 wikitext，全页只有 2,550 字）：

```wiki
==第四幕•翁法罗斯==
{{#ask:[[分类:开拓任务]][[分类:系列任务]][[任务地区::翁法罗斯]]
|?系列任务名 |?任务地区 |?描述 |?任务类型
|format=template |template=开拓任务/行 |sort=所属版本,创建日期}}
```

**结论与依据**：这个页面的正文是 **SMW 服务端渲染**出来的。抓 HTML 去找表格是徒劳的——实测 `<table>` **0 个**、`<tr>` **0 个**。所以必须走 SMW 查询拿索引：

```
api.php?action=ask&query=[[分类:开拓任务]][[任务地区::翁法罗斯]]|?系列任务名|?任务编号|?所属版本
→ 74 页
```

再用页面上的章节卡片逐个核对（75 个链接），补上漏掉的 **1 页**：「魔女的镜中回天」——它的 `任务地区` 写的是「黑塔空间站」（剧情确实发生在空间站），但 `系列任务` 属于 3.2 的「走过安眠地的花丛」，所以按地区查会漏。

**最终**：75 页 = 67 个任务页 + 8 个「系列任务」汇总页（后者没正文，解析时跳过）。

## 3. 剧情顺序：不排序的话语料是「拼音序」

**做什么**：把 67 个任务页排成剧情顺序。

**为什么必须做**：第一次抓完，语料前 10 条是

```
书卷啊，可曾令锋刃回眸（3.3）
争辩啊，代长矛分庭抗礼（3.2）
仇寇啊，且领受金血烧灼（3.1）
```

——这是 SMW 返回的**标题拼音序**，跟剧情毫无关系。任何"随时间漂移"的分析都会失效。

**方法**：不靠版本号硬排，用每个任务页自带的 `前置任务` / `后续任务` 字段建链：

```wiki
|前置任务=*[[诗者啊，从我处诉说天空•上]]
|后续任务=*[[石板啊，为何罔闻那灯影]]
```

**依据**：
- 64 条链边、63/67 页有前置 → 拓扑排序后**链一致性违例 0**；
- 解决了一个靠编号排不对的问题：3.3 里有**两个 `#07`**（「诗者•下」和「石板啊」），靠链才排成 诗者上→诗者下→石板；
- 3.4 是分支结构，有 4 个没有前置的并列起点，用 (版本, 任务编号) 兜底；
- 排序后版本严格 3.0→3.7 单调，首条正是 3.0#01 的开场（帕姆「喂喂」）。

**自检**：`quest-order.json` 的 prev/next 与相邻 order 逐页比对；渲染抽样确认首尾台词。

## 4. 正文获取：为什么存 wikitext 而不是 HTML

**做什么**：每页用 `action=parse&prop=wikitext` 拿原文，存进 `data/raw/wt-cache/`。

**依据**：HTML 渲染后的正文会把结构压平——说话人头像气泡、选项按钮、折叠块都变成 `div`，反而难还原；而 wikitext 里结构是显式的：

```wiki
{{角色对话|模板开始|星穹列车一家人}}
{{角色对话|左|帕姆|文本|喂喂}}
{{剧情选项
|选项1=要跃迁了对吧
|剧情1={{角色对话|右|开拓者|文本|要跃迁了，对吧？}}
|选项2=喂喂
...
```

**另外**：缓存 75 个文件（2.48 MB）后，整条管线可以**离线重跑**，不依赖网络。

## 5. 模板内联展开：不展开会截断正文

**做什么**：在切行之前先把 wiki 模板换成纯文本。

**原文与后果**：

```wiki
:{{颜色|描述|数日后，在命运重渊的车厢坠毁点……}}
```

第一版解析器**先按行切、后清模板**，结果有 **10 条记录正文只剩 `{{颜色`**（内容全丢）、196 条尾部残留 `}}`（其中 194 条是 option）。

**规则与依据**：

| 模板 | 处理 | 依据 |
|---|---|---|
| `{{颜色|x|Y}}` | 取 Y | 颜色只是排版 |
| `{{注音|A|B}}` | 取 A（显示文本） | 游戏里玩家看到的是 A；B 是 ruby 注音，另存见 `03-注音语料.md` |
| `{{黑幕|x}}` | 取 x | 黑幕是剧透遮罩，正文就是 x |
| 未知模板 | 取最后一个纯文本参数 | 兜底 |
| `[[A\|B]]` | 取 B | wiki 链接 |

**自检**：v31 语料里 `{{` 与 `}}` 残留 = **0**。

## 6. 行级状态机：一条一条判，而不是"抓正文"

**做什么**：逐行判断这一行属于什么类型，产出记录。

| 原文形态 | 判定 | 依据/样例 |
|---|---|---|
| `=== 步骤标题 ===` | `step_title` 新段 | 页面用三级标题分流程步骤；第一版只认二级标题，导致整页只剩 1 个步骤 |
| `*角色：台词` | `dialogue` | 台词主体 |
| `{{角色对话|左/右/中\|角色\|文本\|台词}}` | `dialogue` + `scene` | 气泡对白；`模板开始` 带场景名（如「星穹列车一家人」） |
| `{{剧情选项 …}}` | `option`（玩家）+ 分支里的 `dialogue` | 语料保留全部分支（`is_duplicate` 标记重复） |
| `{{短信选项 …}}` | `sms` / `sms_option` | 短信界面，`channel="sms"` |
| `:正文`（行首冒号） | `narration` | 场景/时间跳跃旁白；第一版**整行丢弃了 1,963 行** |
| `{{折叠\|标题=额外对话…}}` | 内部记录 `extra=true` | 可选闲聊，不属主线 |
| `*泰坦悲伤的低鸣*`（整句被 `*` 包住） | `narration` | 舞台指示，不是台词 |
| `{{任务描述\|文本\|地点}}` | `narration` + `location` | 地点信息 |

**关键依据：怎么发现"漏了 `:` 行"的** ——
不是靠猜：把 wt-cache 全文按行首字符统计，发现 `:` 开头有 **1,963 行**，而语料里 from v1 的 `origin` 字段里没有一类来自它们。补上后记录数 24,206 → **26,332（+2,126）**。

**另一处隐性丢失**：`kind=narration` 里有 **894 条**其实是「标签：台词」（如 `永夜之帷，三月七：「…」`、`博识尊[黑塔]：「阿基维利！」`）。根因是说话人正则拒绝含标点/括号的标签。v31 把这些拆成 `dialogue + speaker`，保留 `embedded_from="narration"` 便于回溯。

## 7. 说话人归一：配置驱动，两层结构

**做什么**：把 `speaker` 原始标签映射成 `canonical_speaker`（人物）+ `form`（形态/称号）。

**为什么不能直接合并**：原始标签混了四种东西——
`迷迷`（形态）、`「往昔的涟漪」`（称号）、`「冬霖爵」塞涅卡`（爵位+本名）、`「赛白厄」`（赛飞儿冒充白厄）。

**方法（6 级优先级，命中即停）**：

```
1. speaker_literal_map 精确命中（含 form）
2. canonical.*.speaker_aliases / true_name_map 精确命中
3. 剥称号前缀（「X爵」/「先王X」/「元老X」）后重试
4. 剥成对「」『』、去括号注音后重试
5. form_map 形态表
6. pattern_rules（X之声→X、记忆中的X→X、复合「称号，本体」→本体 + form=称号）
→ 都未命中：canonical=null（不猜）
```

**依据**：
- 称呼来源不是编的：BWiki 角色页 `昵称/外号`（31 页，带 `{{#info:谁这么叫}}`）、`模板:开拓者外号`、SMW 的 `称号/全名`、百度百科/萌娘百科交叉核对；
- **硬规则**来自剧情事实：`卡厄斯 ≠ 卡厄斯兰那`、`铁墓 ≠ 白厄`、`长夜月 = 三月七`、`缇安/缇宁 = 缇宝分身`、`迷迷 = 昔涟早期形态`；
- **效果**：v1 口径 82.54% → 配置 v3 后有效归一 100%（23,090 条非空 speaker 中 22,949 命中 + 141 条非说话人标签）；
- 在 v3.1/final 语料口径是 97.58%——差额来自新增的 2,126 条里有未登记路人（不猜）。

## 8. 清洗：只写 `text_clean`，不动 `text`

**做什么**：原文保留在 `text`，清洗结果写进 `text_clean`。

**依据**：任何下游结论都可能被质疑，必须能回到原文；而分析又需要干净文本。

| 清洗项 | 规则 | 量 | 依据 |
|---|---|---|---|
| `他/她` | → 开拓者 | 117 处 / 110 条 | BWiki 站点级性别占位约定（全站 151 页在用）；同句/紧邻句几乎都有「开拓者」同位语 |
| 例外 | 3.6#07 长夜月的「他/她们俩」保留 | 1 处 | 复数，指两个人 |
| 行内 `*强调*` | 去星号留文本 | 342 对 / 299 条（`*我们*` 273） | 缇宝用「我们」指代分身群体，**语义有价值**，不能删 |
| 模板残留 | 去 `{{ }}`、`<br>`、`[[ ]]` | 216 条 | 解析阶段遗留 |
| 舞台指示 | 整句 `*…*` → `kind=narration` | 19 条 | 是拟声/动作，不是台词 |

**自检**：`text_clean` 里 `{{`/`}}`/`他/她`/`*`/HTML 残留 = **0**。

## 9. 视图与去重：不物理拆文件

**做什么**：加 `view`（`main`/`extra`）、`is_duplicate`、`dedup_group`。

**依据**：
- `{{折叠}}` 里的「额外对话」是**可选闲聊**（1,459 条），做时序分析必须能排除 → `view=extra`；
- 分支转录会产生重复（同一句挂在多个选项下），但**删掉会丢信息**（可能是仪式/口号重复，见 `04` 文档）→ 保留全部、只标记。

## 10. 质检：怎么证明"没漏、没串、没脏"

**做什么**：三份 QA 报告 + 渲染比对。

**依据（每条都是可复算的）**：
- **顺序**：`id` 连续、`order` 1–67 连续且单调、版本 3.0→3.7 严格单调、67/67 页与 `quest-order.json` 对齐；
- **完整性**：0 空文本、除可选字段外 0 缺失、`lines.txt` 逐行与 jsonl 一致；
- **渲染比对**：把 BWiki 用浏览器渲染出的正文和语料比对——单页（849 条）包含匹配 625 条；非折叠记录命中 85.1%、折叠记录 14.5%（折叠默认隐藏，符合预期）。这一步还**推翻了我自己**的一个旧结论「未命中全在折叠块内」——非折叠也有 106 条没命中；
- **未归一清单**：434 个未匹配标签逐条列出（句数/版本/例句），供人工决定。

## 11. 外部复核：两轮，共 45 条修订

**做什么**：把配置和文档交给外部模型（Gemini）交叉比对，逐条采纳。

**依据（它抓到的都是真错，有原文可证）**：
- 关系反转：`老日` 是**开拓者叫星期日**，我写反了；
- 越界版本：`欢愉主/雷主` 是 4.2 内容，3.0–3.7 用不到；
- 梗名污染：`粉色芭芭拉`/`盾丹`/`炖蛋`/`纠缠之缘` 是社区梗，不能进正式 aliases；
- **优先级穿透 Bug**：`canonical.萨姆.speaker_aliases` 会和 `literal_map` 抢"萨姆"，导致带引号的变体归错角色；
- 账面不一致：`meta.version` 写成字符串、覆盖率还是旧数字、`label_count` 没同步。

**我自己也修了一处它没提的**：`pattern_rules` 里有两条把**说明文字**写进了 `form` 字段，下游把说明当数据，污染了 204 条记录的 `form`。
