## P0（事实错误 / 会误导）

### P0-1 图上「事件」标注是按**任务页**对齐的，箭头和 ▶ 行会落在事件发生前 5–19 个出场步

- **位置**：第 2–5 章所有角色卡的折线图箭头 + 事件表 ▶ 行。
- **页面原文**：图注「箭头=图上标出的关键事件，标题见下表」；例如白厄「174 3.4 ▶ 兑现/刀子 见证翁法罗斯的真相」、阿格莱雅「60 ▶ 兑现/刀子 前往云石天宫」、刻律德菈「12 ▶ 神谕首现/吟诵/刀子 归还「负世」的火种」、遐蝶「87 ▶ 神谕首现/吟诵 向祭坛左侧「预言书库」前进」。
- **问题**：`chars/*.json` 的 `in_oracle_first / in_recitation / in_fulfillment / in_knife` 是按**任务页（task）整块**打标的，不是按事件所在 segment；`ANNOT_FLAGS` 又「各取该角色最早一次」，于是箭头落在该任务页的**首个出场步**，不是事件步。逐条核对：
  - 白厄：箭头 174（3.4|点燃|2「见证翁法罗斯的真相」），但 v2 的 O09 `event_segments=3.4|点燃|15`、`current_filled_fulfillment=3.4|粉碎|6`（#16719 实际在 3.4|粉碎|6）。
  - 阿格莱雅：箭头 60（3.3|金丝|2「前往云石天宫」），v2 的 O01 `event_segments=3.3|金丝|7`、filled=3.4|回返|21（#16615）。
  - 缇宝：兑现箭头 48（3.1|门扉|2），v2 事件=3.1|门扉|4；神谕首现箭头 61（3.1|来路|2），但 O02 原文 #7939 在 3.1|来路|17、#8049 在 3.1|来路|21。
  - 刻律德菈：箭头 12（3.5|囚人|4「归还火种」），O11 全篇唯一出现 #20228 在 3.5|囚人|15（步 20「展望书中的繁星」）。
  - 遐蝶：箭头 87（3.1|来路|2），O04 首次出现 #8186 在 3.1|来路|21（步 88）。
- **依据**：`oracle-fulfillment.v2.json` 的 `event_segments / current_filled_fulfillment`；`oracle-citation-coding.json`（O11 仅 #20228；O02 #7939/#8049 段）；`data/chars/*.json` 行级 flag 与 `segments.jsonl` 的 `step_title` 对应关系。
- **建议改法**：标注层不要用「任务页 flag 最早一步」，改为直接用 citation coding / v2 的 `segment_id` 定位到 segment 首步；若保留现逻辑，图注必须写明「箭头=事件所在**任务页**的首个出场步，可能早于事件本身」。

### P0-2 事件表既不是全部事件、也不是按时间排序，但版式让读者当成「事件清单」

- **位置**：第 2–5 章角色卡下方事件表；尤其白厄（步 151→174→171→201）、赛飞儿（1→24→7→40）、昔涟（1→177）。
- **页面原文**：表头「步｜版本｜事件｜剧情标题」，正文旁无「仅示例」说明；白厄表行「151 … ▶ 神谕首现/吟诵」「174 … ▶ 兑现/刀子」「171 … 吟诵/刀子」「201 … 吟诵」。
- **问题**：`App.jsx` 的 `evRows` 先放「图上标注行」、再按事件类型各补 1 条代表（最多 6 行），所以 ①行序不是按步号（171 排在 174 后）；②表只列了该角色全部事件步骤中的一小部分，读者会以为这就是全部；③`EVENT_FLAGS` 里还有「关键事件」（绿色彩点），但表的「事件类型」被 `filter(n => n !== '关键事件')` 过滤，导致绿色点在图上有、表里没有、图例也没有。
- **依据**：`App.jsx` L385–405（`evRows` 构造）、L237–243（EVENT_FLAGS 含 `in_key_event`）；可见文本中三张表的步序均为非升序。
- **建议改法**：按步号升序排；表头/表下加「共 N 个事件步骤，仅列图中标注 + 每类代表 M 行」；并给 5 种彩点（含「关键事件」）加一行颜色图例，或去掉「关键事件」的点以与表一致。
