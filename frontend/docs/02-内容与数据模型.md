# 内容与数据模型

## 内容组织

内容按讲解顺序组织，而不是按组件或图表组织：

1. 原始文本；
2. 结构化文本；
3. NLP 表示；
4. 检索和比较结果；
5. 人工解释和剧情结论。

每一步都同时展示一个很小的输入/输出例子，避免只讲术语。

## 核心对象

```ts
type Oracle = {
  oracle_id: string
  text: string
  holder: string
  titan: string
  citations: Citation[]
  fulfillment: Fulfillment
  meaning_changes: MeaningChange[]
}

type Citation = {
  record_id: number
  segment_id: string
  version: string
  task: string
  step_title: string
  speaker: string
  stage: string
  quote: string
  evidence: string
}

type Fulfillment = {
  recitation_segment?: string
  event_segments: string[]
  type: "literal" | "reversal" | "misalignment" | "recognition" | "mixed"
  evidence: string
}

type MeaningChange = {
  event_id: string
  event_name: string
  before: string
  after: string
  evidence_record_ids: number[]
  confidence: "high" | "medium" | "low"
}
```

## 必须区分的概念

- **吟诵段**：角色原样念出神谕的位置；
- **事件段**：神谕真正兑现、反转或错位的位置；
- **词面相似度**：TF-IDF/BM25 等方法测出的文本相关性；
- **语义相似度**：句向量空间中的接近程度；
- **含义变化**：需要用前后文和剧情关系解释，不能直接用一个相似度数值代替。

## 前端数据快照

`frontend/data/` 是当前版本的副本，主要包含：

- `segments.jsonl`：步骤和按顺序排列的主线记录；
- `oracles.jsonl`：13 条神谕及引用候选；
- `oracle-citation-coding.json`：34 次引用的阶段编码；
- `oracle-fulfillment.v2.json`：吟诵/事件段和兑现类型；
- `key-events.json`：30 个含义变化事件；
- `knife-scenes.json`：36 个刀子/高光候选场景；
- `character-trajectory-all.json`：角色轨迹和覆盖；
- `oracle-similarity-curves.json`：相似度曲线；
- `style-compare-results.json`：语体全量与话题匹配结果；
- A/B/B2 分数与标注文件：只用于方法解释和候选发现。
