# 完整分析思路：从剧情文本到“命定如何改变含义”

这份文档根据 DS 当前已经完成的语料、配置、模型、报告和 L3 精读结果整理。它描述的是最终报告应该如何讲清楚项目，而不是另做一套实验。

## 1. 研究问题到底是什么

项目不是要训练一个模型去预测剧情，也不是要判断哪一句最催泪。核心问题是：

> 翁法罗斯的“命定”如何被写成语言，如何被角色引用、接过、交出或改写，并在后续剧情中获得新的含义？

这个问题有两个层面：

### 主线：神谕的文本生命周期

把神谕当作一种会在剧情中移动的语言对象，追踪它经历了什么：

```text
神谕原句
→ 被谁说出
→ 被谁转述或解释
→ 是否被本人认领
→ 是否被改写
→ 在什么事件中兑现
→ 兑现后原句的含义变成什么
```

这条主线是项目的核心结论来源。

### 扩展：叙事显著性检测

比较两种寻找重要片段的方法：

- 普通方法只看死亡、牺牲、告别、负面情绪、停顿等局部词面信号；
- 优化方法再加入身份变化、语义突变、母题回收、时间视角变化和不可逆状态变化。

这个扩展要证明的不是“机器能测出读者情绪”，而是：**只看强烈词汇会漏掉昔涟诞生这种词面不强、但叙事意义很重的片段。**

## 2. 第一层：建立可追溯的剧情语料

### 2.1 原始输入

输入是翁法罗斯 3.0–3.7 主线剧情，共 67 个任务页。解析后得到：

- 26,332 条台词、旁白或选项；
- 约 566,798 字；
- 723 个剧情步骤；
- 8 个版本（3.0–3.7）。

一条记录不是孤立句子，而是带有来源位置的对象：版本、任务、步骤、说话人、原始文本、记录类型和剧情顺序都保留下来。

### 2.2 为什么要结构化

如果只把所有剧情拼成一个大文本，后面即使找到“汝将肩负骄阳”，也不知道它在哪个任务、哪个步骤、由谁说出，更无法判断它是神谕原文、角色引用还是结局宣告。

因此先把文本整理为两种粒度：

1. **记录级**：一句台词、旁白或选项，用于上下文、角色和引用核对；
2. **步骤级**：同一个剧情步骤聚合后的文本，用于排序、曲线和显著性评测。

步骤实例使用 `version|task|step_idx` 作为唯一 ID，步骤标题只用于显示。这样同名的“剧情内容”不会被误当成同一个片段。

### 2.3 角色规范化

同一角色在文本中可能使用本名、别名、形态名或称号。例如“赛法利娅—赛飞儿”“迈德漠斯—万敌”“卡厄斯兰那—白厄”。

处理方式不是抹掉原称呼，而是同时保存：

- 原始说话人；
- 规范角色 `canonical_speaker`；
- 形态或别名 `form`；
- 角色类型和所属分组。

这样既能把同一角色的语言合并统计，又能研究“角色在什么时候换了称呼”。

主线角色口径固定为：11 位黄金裔，以及列车组的开拓者、三月七、丹恒。其他人物不进入主线角色分组。

### 2.4 重复与系统文本

剧情中存在回忆、吟诵、战斗提示、重复台词、选项和折叠对话。它们不能简单删除，因为重复本身可能是母题回收或时间循环的证据。

所以数据采取“标记而不是粗暴删除”的方式：

- `repeat_kind` 标记普通重复、母题、仪式、停顿或结构性重复；
- 选项单独保留，不混入主对白文本；
- 系统提示和战斗动作保留，但用 `system_only`、`low_content` 等字段标记；
- 主实验主要使用有实际对白/旁白的 686 个步骤，原始 723 步仍可回溯。

这一层的输出是 `amphoreus.final.jsonl` 和 `segments.jsonl`：前者保留逐条原文，后者提供步骤级分析单位。

## 3. 第二层：建立神谕对象，而不是只做关键词搜索

### 3.1 神谕表

从固定句式、注音文本和人工核对中建立 13 条神谕表。每条神谕至少有：

- 神谕原文；
- 持有者和泰坦；
- 关键词和注音隐喻；
- 首次出现位置；
- 所有引用位置；
- 可能的兑现段；
- 兑现类型和证据。

注音表提供了“表面词—真实所指”的额外线索。例如神谕中的意象不一定等于字面事件，注音可以帮助判断它在世界观中的实际指向。

### 3.2 吟诵段和兑现段必须分开

这是 DS 工作中最重要的口径之一：

- **吟诵段**：角色原样念出或引用神谕的位置；
- **兑现段**：剧情实际让神谕发生、反转或错位的位置。

两者可能是同一步，但不能默认是同一步。比如角色在临死前念出神谕，既可能是在宣告兑现，也可能只是把预言再次说出来；真正的意义变化还要看动作、关系和后果。

这一区分也是后面检索实验失败的原因之一：如果把“念出神谕的地方”当作兑现答案，模型只要找回原句就能得分，结果会虚高。

## 4. 第三层：研究神谕怎样被写成语言

这一层回答：神谕在形式上是否和普通对白不同，角色引用时是否靠近或偏离这种形式。

### 4.1 对比的文本组

DS 实际比较了三类文本：

1. 神谕原文；
2. 普通剧情对白；
3. 角色引用、转述或改写神谕时的对白。

不能直接把“神谕”和“所有对白”简单比较，因为神谕谈抽象命运，普通对白谈具体行动，主题差异会冒充语体差异。因此报告同时保留全量比较和话题匹配比较。

### 4.2 可测的语言特征

包括：

- 文言虚词和文言色彩；
- 第二人称“汝”；
- 情态词和预示词，如“将”“必”“终”；
- 抽象名词和命运相关词；
- 句长、停顿、排比和重复结构；
- 角色自称、对他人的称呼和人称变化。

这一步使用词频、TF-IDF 和简单句式统计，因为问题是“有没有可观察形式”，不需要用复杂模型制造不可解释的结论。

### 4.3 这一层能得出什么

可以说：神谕有一套稳定的句式和语体，角色引用它时会出现三种现象：

- **靠拢**：保留原句或让自己的话带上神谕腔调；
- **偏离**：换掉人称、对象、语序或解释方式；
- **反向改写**：词语还在，但角色把它变成另一种价值判断。

不能说：神谕“更文学”、某个角色“更高级”，或者某种语体必然让玩家更感动。统计特征只说明语言形式不同。

## 5. 第四层：研究神谕怎样被角色接管

引用编码不是简单的“出现过几次”，而是给每次引用标记它在叙事中的作用。DS 的 34 处引用被编码为原文出现、旁白转述、他人解释、本人引用、主动认领、结局宣告、改写反转等阶段。

从这些轨迹中，L3 精读归纳出几种接管方式：

### 5.1 沉默与让渡：白厄

白厄并不反复谈自己的神谕。真正关键的动作是他把“救世主”的名号和责任交给开拓者。

因此白厄的命定不是“本人不断宣告我会成为救世主”，而是：

```text
神谕被转述
→ 白厄承认它属于自己
→ 白厄把名号交给更合适的人
→ 昔涟在终局揭示这句话是她写下的希望
```

白厄是主线重点，因为他把“承受命定”变成了“主动交付命定”。

### 5.2 全链引用：阿格莱雅

阿格莱雅的神谕从原文出现、本人引用到结局宣告，形成完整链条。她不是被动等神谕发生，而是亲口说出“现在，是时候将其兑现了”。

这说明“兑现”在文本中不仅是一个事件，也是角色主动宣布的语言行为。

### 5.3 提炼：缇宝

缇宝的神谕并不是简单从某一句泰坦原话复制出来，而是从多处散文式判词中提炼为一句可以传播的箴言。

这里的语言变化是：

```text
分散的世界观判词
→ 角色提炼
→ 固定的短句
→ 在告别和终局中再次回收
```

神谕不是永远固定存在的原文，也可能是角色把复杂叙事压缩后创造出来的。

### 5.4 改写：遐蝶

遐蝶并没有简单否认神谕，而是改变它的价值解释：从“相拥之后便是永恒离别”转成“拥抱不再是冰冷的剥夺，而可以携带爱”。

这里词语可能仍然相似，但关系和价值已经变了。这也是为什么单纯相似度不能代表含义。

### 5.5 镜像与追认

海瑟音和刻律德菈的两条神谕使用同一组词，只交换语序。TF-IDF 几乎无法区分，但剧情中谁说、谁继承、哪一部分落到谁身上，完全不同。

那刻夏则是“追认型”：相关事件先发生，神谕原句后来才出现并被解释为对既成事实的复述。命定的时间方向因此可以倒置。

## 6. 第五层：研究神谕如何兑现和改变含义

13 条神谕逐条建立“意义履历”，不是只给一个“命中/未命中”标签，而是记录：

```text
原句
→ 早期解释
→ 角色态度
→ 事件发生
→ 兑现时保留了什么
→ 哪些部分被反转或换了对象
```

目前的分析把兑现区分为字面、反转、错位和追认等类型。报告应该以神谕为单位逐条讲，而不是先展示一张类型比例图。

### 6.1 字面兑现

例如万敌“背后负创而死”、赛飞儿“亡于分文”、风堇留在天空等。文字中的关键意象在剧情中可以被直接指认。

### 6.2 反转兑现

遐蝶把“拥抱后的离别”改写为带有温度的拥抱；海瑟音放弃神谕中“征服”的字面目标，把长眠转成守墓、醉梦和为自己歌唱。

### 6.3 错位兑现

刻律德菈和海瑟音的镜像神谕把同一词语分配给不同对象。刻律德菈在海中完成的是对律法的征服，而不是传统意义上征服群星。

### 6.4 追认和双线

那刻夏的事件先于神谕出现；万敌的“背后负创”在主线和记忆线中形成跨轮回的两次实现；昔涟的“收梢于花开时”既有 3.4 的意义转折，也有 3.7 的最终收梢。

## 7. 第六层：用检索方法做“定位实验”，而不是让它替代解释

为了检验机器能否自动找出兑现段，DS 做了多轮检索：关键词、TF-IDF（词/字符）、BM25、LSA 和 SBERT。

### 7.1 输入和输出

- 输入：一条神谕文本；
- 候选：686 个步骤；
- 输出：按相似度排序的步骤列表；
- gold：人工指定的兑现段。

评价指标包括 MRR 和 Recall@k。它们只回答“正确的兑现段排得靠不靠前”。

### 7.2 为什么检索失败

v3 把吟诵步骤从候选池剔除后，只剩 7/13 条神谕可评；最佳 MRR 只有 0.132，SBERT 甚至只有 0.012。原因不是“语义模型没有价值”这么简单，而是任务本身包含三个困难：

1. 兑现段和吟诵段常常是同一段，gold 与查询天然重叠；
2. 真正的兑现可能依靠动作、关系、道具和剧情后果，而不是原句词汇；
3. 长步骤会稀释局部语义，回忆和另一条时间线又会破坏简单顺序。

因此检索结果的正确结论是：**现有自动方法适合找候选和展示失败边界，不能替代神谕履历的人工解释。**

## 8. 第七层：建立共享文本表示和角色轨迹

DS 没有为每个角色训练一个独立模型，而是使用一套共享的文本空间：

- 记录级 TF-IDF；
- 步骤级词/字符 TF-IDF；
- LSA 降维表示；
- bge-small-zh-v1.5 句向量；
- 角色质心和按版本的角色质心。

一条台词先变成向量，再按角色台词平均得到角色质心；按版本平均则得到角色语言轨迹。角色轨迹的作用是观察“某角色在不同阶段说话方式和神谕相似度如何变化”，不是建立“白厄模型”或“昔涟模型”。

主线展示中，所有黄金裔和列车组成员都可以有轨迹卡；白厄和昔涟展开完整的上下文、引用、关键事件和 L3 解释。

## 9. 第八层：叙事显著性检测的对比实验

### 9.1 为什么要做这个扩展

项目最初想找“刀子”，但读者情绪没有可靠的弹幕或连续观看数据，直接测“玩家是否痛苦”不现实。因此把目标改成可观察的文本问题：

> 一个片段之后，角色身份、关系、世界知识、时间结构、叙述视角或前文意义是否发生了持续变化？

### 9.2 标注对象

标注单位仍是步骤实例，但长步骤内部按句和滑窗计算特征。显著度为 0–3：

- 0：普通推进；
- 1：局部信息或关系变化；
- 2：明显的叙事状态变化；
- 3：重大转折或前文意义重写。

另加类型：身份、记忆、神谕、关系、世界规则、牺牲和母题回收。

现有 74 条标注是 LLM 辅助和独立盲标的稳定性材料，κ=0.788 说明标注较稳定，但不代表客观真值或准确率。

### 9.3 检测器 A：普通词面/局部情绪基线

A 对每个步骤计算死亡、牺牲、告别、负面情绪、第一人称脆弱表达、停顿、短句、感叹和疑问等局部特征，再按固定先验权重合成分数。

它代表一种容易理解的做法：哪里出现明显的刀子词，哪里就优先看。

### 9.4 检测器 B：结构增强排序

B 在 A 的基础上加入：

- 步骤内滑窗的语义突变；
- 新身份、新关系和世界规则的集中出现；
- 称呼或形态变化；
- 回忆、循环、未来和故事内故事等视角切换；
- 神谕、歌谣、称呼、道具和重复台词的母题回收；
- 章节、任务和场景转折位置；
- 不可逆状态变化。

B 的目的不是制造一个“更懂文学”的模型，而是测试加入结构证据后，排序是否能补回 A 漏掉的片段。

### 9.5 评测和真正结论

A、B 在同一个 686 步候选池上独立排序，比较 Precision@k、Recall@k 和案例差异。标注集只用于留一验证和案例核对，不用于调权重。

真正重要的不是某个总分，而是三类对照：

1. A 排得很前、B 也排得前：显性刀子，词面足够；
2. A 排得靠后、B 排上来：结构回收或身份变化被补回；
3. 两者都失败：说明需要人工重新定义边界或补充上下文。

昔涟诞生段是第二类最重要的案例：强烈情绪词不多，但“诞生之地—记忆种子—讲述者/听众—水晶花—收梢—德谬歌诞生”形成连续结构回收。

### 9.6 DS 当前实际结果

在 74 条人工/盲标样本上，A 与显著度等级的 Spearman 相关为 **0.401**，B1 提升到 **0.581**。显著样本（等级 ≥2）的排名中位数从 **159.5** 改善到 **123**，进入 Top100 的数量从 **7/28** 增加到 **13/28**。

这说明 B1 的结构特征确实提供了额外信息，但它不是一个已经验证准确的分类器：Top20 中显著样本仍只有 2 个，且 B1 与步骤长度的相关性上升到 **0.683**，长步骤更容易积累结构信号。

DS 还做了 B2，试图用句级相邻距离和半步对比修复短步骤。B2 的总体相关降到 **0.541**，Top100 显著样本变成 **12/28**，因此当前报告应采用 B1，保留 B2 作为“短步骤修复没有成功”的诊断实验。

这组结果应该这样讲：

```text
A 能找到显性的死亡/告别/负面词片段
→ B1 加入结构信息后，部分身份/记忆/母题/神谕片段排名上升
→ B1 仍受长度偏差影响
→ B2 试图修复短步骤，但没有改善总体结果
→ 最终仍需回到原文和关键事件解释
```

## 10. 第九层：用 L3 精读把数字翻译回剧情

机器结果最后必须回到原文。DS 为 14 个角色建立了逐条全量精读笔记，每份笔记包含：

- 分版本语言弧线；
- 角色称呼和形态变化；
- 神谕相关引用；
- 母题和重复台词；
- 低显著性但重要的片段；
- 机器候选和人工判断的差异；
- 可核对的 record_id。

同时，30 个关键事件被整理成“含义之前→含义之后”。这是报告解释层的主要证据格式：

```text
事件发生前，文本让读者如何理解角色/世界？
事件发生后，哪个身份、关系、规则或前文解释被改写？
证据台词和数据特征分别是什么？
```

36 个刀子/高光场景则作为对照材料，不把“刀子”直接当成客观标签。

## 11. 最终报告应该怎样讲白厄和昔涟

### 白厄：命定从“背负”变成“交付”

白厄的主线不是简单地“神谕实现了”。他的关键变化是：

```text
骄阳与救世主的职责落在他身上
→ 他承认这份命定
→ 他把救世主之名交给开拓者
→ 卡厄斯兰那从个人名字变成英雄的公共称谓
→ 昔涟揭示这句神谕本身是写给他的希望
```

这里 NLP 能提供：引用位置、说话人变化、词面相似度、角色轨迹、关键事件前后字段。真正的含义由“交付”这个动作和前后语境解释出来。

### 昔涟：命定从“被写下”变成“写故事的人”

昔涟的主线是最终的元叙事回收：

```text
迷迷/记忆形态作为被照看、被讲述的存在
→ 找回关于德谬歌和自身的记忆
→ 成为讲述者，同时也是最专心的听众
→ 通过水晶花寓言改写“破碎”的意义
→ 在花开时收梢
→ 德谬歌作为“心”诞生
```

O13 不是单个死亡句的命中，而是三千万世故事、记忆、讲述和水晶花寓言共同构成的含义变化。它正好说明为什么只找“死亡/告别/牺牲”会漏掉真正的叙事冲击。

## 12. 课程方法各自放在哪里

| 方法 | 在项目中的实际作用 | 是否主线必须 |
|---|---|---|
| 结构化抽取 | 保留剧情位置、说话人和步骤 | 必须 |
| 规则/词表 | 找神谕、别名、引用候选 | 必须 |
| TF-IDF | 词面检索、语体特征、显著性基线 | 必须 |
| BM25 | 经典词面检索对照 | 建议 |
| LSA | 低维词面表示，作为检索对照 | 可简述 |
| 句向量 | 语义相似度、步骤曲线、语义突变 | 必须解释，结论要谨慎 |
| 角色质心 | 观察角色语言的总体方向和版本漂移 | 作为证据 |
| 人工/L3 精读 | 把模型结果翻译成含义 | 必须 |


## 13. 最终应当怎样理解这些数字

- TF-IDF/BM25 高：说明词面接近；
- 句向量高：说明模型认为语义方向接近；
- 角色曲线变化：说明角色台词在共享向量空间中的语言分布变化；
- A/B 排名变化：说明结构特征是否帮助定位候选；
- MRR/Recall：说明检索把人工指定片段排得多靠前；
- κ=0.788：说明重复标注的一致程度；
- L3 和关键事件：说明这些数字在剧情中具体意味着什么。

任何一个数字都不能单独等于“含义”“刀子”或“读者情绪”。最终结论必须同时有：原文证据、数据位置、方法输出和人工解释。
