# 前端改版：方法与结果融合（核心问题与改版方案）

> 背景：当前前端把"方法讲解"和"结果展示"分成两个部分。读者看到的是：
> 先用抽象语言讲完 TF-IDF/句向量/引用编码（没有具体对象），再翻到后面看曲线、排名、角色卡（换了一批例子）。
> **问题不在内容，而在信息组织：方法与结果没有落在同一个对象上。**
> 本文只讨论页面结构与分析逻辑的融合，不写前端实现。

## 1. 诊断：为什么"分开"就难看

| 现状 | 读者感受 |
|---|---|
| 方法章用"一句话台词"举例 | 学完不知道这方法用在哪 |
| 结果章突然出现 686 步、14 角色、13 神谕 | 不知道这些数字从哪来 |
| 方法与结果用的是**不同例子** | 无法建立"A 方法 → B 结果"的因果 |
| 每屏"四问四答"（方法/原理/为什么/变成什么）里的"变成什么"只占一小块 | 方法和输出不像同一件事 |
| 图、表、原文分散在不同章节 | 无法"从结论回原文" |

一句话：**没有一条贯穿的"对象链"**。

## 2. 改版原则（五条）

1. **单一对象主轴（spine object）**：全程追一个具体文本对象——推荐 **O09 的三次出现**：
   - `#15680` 旁白「白厄在麦田中梦见一道神谕」（梦/转述）
   - `#16719` 白厄「诚如神谕所示……愿这名号能代我同行」（交出）
   - `#26045` 昔涟「诚如神谕所示：『汝将肩负骄阳，直至灰白的黎明显著』」（揭示书写者）
   后面所有步骤都围着这三个 record 展开，不再换例子。
2. **同一屏内做"前后对照"**：每屏固定 = **对象的前一状态（左）→ 方法操作（中，1–2 句）→ 对象的新状态（右）**。
3. **方法从结果里长出来**：不先讲完方法再用，而是"先看到现象 → 引出方法 → 立刻用同一对象展示方法带来的变化"。
4. **每屏四问嵌在对象上**（不再是独立章节）：这步是什么 / 原理一句话 / 为什么用 / 对象变成了什么。
5. **判读紧跟结果**：每屏右下角固定"这一步能说明 / 不能说明"，并带 record_id 回原文。

## 3. 改版后的 10 屏结构（每屏同一对象）

> 对象卡（sticky）：始终显示"当前对象：O09 / #15680、#16719、#26045"，以及它已经获得的属性（记录号→字段→引用阶段→曲线位置→精读发现）。

| # | 屏标题 | 对象：前 → 后 | 方法（1–2 句，嵌在中间） | 结果（右栏，真实数据） | 能/不能 |
|---|---|---|---|---|---|
| 1 | 三个句子，一段命定 | 原始网页大段文本 → 切出三行台词 | 清洗/分段：一行一句、可回溯 | 三行原文 + 各自位置 | 能定位；不能解释含义 |
| 2 | 让每句话有坐标 | 三行 → 每条带 `version/task/step/speaker` | 结构化、说话人归一 | 三条记录卡（字段全显示） | 能追到剧情位置 |
| 3 | 从一句话到一条神谕 | `#15680` → O09 候选 → O09 卡 | 规则匹配+人工确认（展示匹配词与阈值） | 13 条神谕表、O09 的 34 处引用位置 | 能抽神谕；不能自动判兑现 |
| 4 | 词面检索为什么霸榜 | O09 当 query → 686 步排序 | TF-IDF：按词计数、只看字面 | 排名表：吟诵段第 1，兑现段很后 | 能找"引用"；不能找"兑现" |
| 5 | 把吟诵排除之后 | 同一 query → 剔除吟诵步 → 排名重排 | 去干扰项、事件段 gold | **v3：7/13 可评、最好 MRR 0.132** | 能证明"自动找兑现失败" |
| 6 | 换成语义向量呢 | 同一 query → 句向量曲线 | 句向量：看语义接近 | 曲线（峰值、3.5 假峰、K36 自我匹配问题） | 能看形状；不能当含义 |
| 7 | 引用是谁说的 | O09 的 4 处引用 → 阶段时间轴 | 引用编码：原文/转述/本人/改写/宣告 | 34 处引用台账（可点开原文） | 能看"谁在接管" |
| 8 | 读完全部台词才发现 | 白厄 2,550 条、昔涟 2,393 条 → L3 发现 | 全量精读（上下文窗口、覆盖自证） | "白厄几乎不引用自己的神谕"等发现（带 record_id） | 能解释；不能统计推断 |
| 9 | 三种接管方式对照 | 白厄（沉默）/阿格莱雅（全链）/缇宝（提炼） | 同一套引用编码横向比 | 三人对照表（同一指标） | 能比较；不能证明因果 |
| 10 | 收梢：同一句话的三次变形 | O09 三次出现 → O13/水晶花/明天见闭环 | 把前面所有对象收束 | 结论一句话 + 数据追溯链 | 能回答研究问题；不能超出文本 |

**关键变化**：第 4–6 屏的方法（TF-IDF/句向量/事件段 gold）不再单独成章，而是**当 O09 的检索结果出现异常时现场解释**；第 7–9 屏的"引用编码/L3"也是围绕同一对象展开。

## 4. 每屏的统一版式（数据契约）

每屏一个 JSON 即可驱动（示意）：

```json
{
  "screen_id": "04-retrieval-lexical",
  "object": {"oracle_id": "O09", "records": [15680, 16719, 26045]},
  "before": {"kind": "query", "text": "汝将肩负骄阳，直至灰白的黎明显著"},
  "method": {"name": "TF-IDF 词面检索", "why": "先建可解释的基线", "one_liner": "按词计数，只看字面"},
  "after": {"kind": "ranking", "rows": [{"rank": 1, "segment": "3.0|...|...", "score": 0.72, "record_id": 15680}]},
  "evidence": {"files": ["data/plot_data/f15_retrieval_v3.csv"], "meta_sha256": "..."},
  "can": ["说明词面方法能找到引用句"],
  "cannot": ["不能说明找到了兑现事件"]
}
```

数据来源全部用根目录现成产物（`data/plot_data/`、`data/config/`），每屏右下角显示"数据文件 + sha256 前 8 位"，保证可核。

## 5. 与现有 docs 的关系

- `03-NLP方法教学链路.md`：保留其"四问"框架，但**拆进每屏**，不再单独成章；
- `04-交互与页面设计.md`：把"页面顺序"改为上面的 10 屏，并把"左中右+底部"固定版式改为**同一屏的前后对照**；
- `08-完整分析思路.md`：作为每屏判读的文字底稿，按对象重组（已接近，主要是把方法与结果合并）。

## 6. 验收标准（改版后自查）

1. 随机抽一屏，问"这屏的方法是什么、结果是什么"——两者必须是**同一个对象**；
2. 每屏都能从结果点回 `record_id` 原文；
3. 全站没有"纯方法、无数据"的独立章节；
4. 全站没有"纯结果、无方法解释"的独立章节；
5. 图的每个点都能追到 `data/plot_data/` 的配对数据；
6. 口径警告（相似度≠含义、LLM 辅助、检索失败）出现在**对应屏**，而不是集中在末尾。
