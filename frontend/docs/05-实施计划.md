# 前端实施计划

## 阶段 0：准备线性讲稿

- 固定“原始文本→结构化→抽取→词面表示→语义表示→结构分析→案例解释→结论”的顺序；
- 每一步写清方法、原理、理由和输出；
- 以白厄和昔涟作为重点分析对象，同时为完整角色名单保留统一展示位置。

## 阶段 1：制作 PPT 式页面

- 每个步骤一页或一个连续区块；
- 左边讲方法，中间放输入，右边放输出；
- 只画必要的时间线和相似度曲线；
- 所有图中使用事件名称，不使用密集散点。
- 角色区默认展示全部 11 位黄金裔和 3 位列车组成员。

## 阶段 2：补充数据证据

- 给每个案例接入原文、版本、任务、步骤和 record_id；
- 将图表上的点连接到对应文本；
- 增加方法限制和当前数据快照说明。

## 阶段 3：质量核对

- 所有事件标题可回到 `segment_id`；
- 所有引用可回到 `record_id`；
- 图片/图表数值与数据快照一致；
- 前端不把相似度写成含义强度；
- LLM 辅助标注、检索负结果和数据限制都有说明；
- DS 后续更新不会悄悄改变 frontend/data 快照。

## 当前不做

- 不先做完整 723 步密集散点图；
- 不做复杂仪表盘、关系网络和多层筛选；
- 不把 A/B1 分数当成文学结论；
- 不为了课程章节强行加入未实际使用的复杂模型；
- 不公开分发游戏原文语料。
