## 这个项目在问什么

翁法罗斯的黄金裔生来背着一句「神谕」，命定像钉子一样钉在身上；而主线做的正是让角色**重新解释、拒绝、交换、改写**这些句子。这个项目把这件事落到可测量的语言问题上：

1. **命定被写成了什么样的语言？** —— 13 条神谕的文体、词汇、与普通台词的语体差异；
2. **角色怎样认领或改写它？** —— 引用轨迹、称呼变化、镜像神谕、反转解释、从他人话语中提炼；
3. **NLP 能不能找到「兑现」？** —— 相似度、检索实验与检测器，到底能帮上多少忙、在哪里失效。

方法上只做两件事：把文本变成**可比较的向量**（词频加权 / 语义向量），再用**剧情证据**（record_id、引用阶段、兑现事件）逐条核对。

## 核心结论一览

1. **两种表示分工明确。** 词频加权回答「有没有说到同一批词」，语义向量回答「是不是在说相近的事」；两条线同时抬高才算语言层面较强的证据，只有语义线抬高时要警惕「泛化假峰」（`f13`、`f14`）。
2. **13 条兑现：字面 10、反转 2、错位 1**；另有三个结构标签不计入类型：O03 双线、O06 追认、O13 两段。类型是人工读文本判定，相似度只用来找候选段。
3. **镜像神谕 O10/O11 用词相同、只换语序**：词频曲线 686 步逐点相等（最大差 0），语义只差 0.018 → 两种表示都分不开，归属只能看引用与兑现的行为（海瑟音替刻律德菈念 O11；刻律德菈本人 0 次引用）。
4. **词频对「沉默」和「改写」是盲的**：白厄的 O09 在词频里只排第 3（0.032）、语义第 10；缇宝的 O02 只到第 6（0.011）。改写要靠同一故事的多版本互比（句向量 0.79–0.87、词频只有 0.28–0.47），而不是看「离自己那句命定多近」。
5. **「明天见」23 条 vs 「明天」108 条**：缇宝承载 13/23，昔涟谈「明天」17 次却只说 1 次「明天见」。3.1 的 9 次里缇宝占 6 次（说话人熵 1.45 bit），3.7 的 5 次分给 5 个人（2.32 bit）——母题的扩散发生在「谁在说」，而不是「说了几次」。
6. **角色曲《昔涟》唱的并不是她自己的命定**：14 个角色里她最近（0.586），但三月七 0.584 紧咬；歌曲最像的神谕是 O04「相拥之后便是永恒的离别」（0.484），不是她自己的 O13（0.416，第 5）。相似度只回答「语言上像谁」。
7. **水晶花寓言是「保义换词」的完整样本**：三版句向量 0.79–0.87、词频 0.28–0.47；曲线真峰在步序 663（词频 0.252 + 语义 0.785，落点正是终局再写 `#25226–#25230`），3.6 大墓/重逢则是只有语义线抬（0.66 / 0.06）的假峰。
8. **语义相似度不能用来看「角色整体像哪条命定」**：SBERT 向量存在很强的共同方向（全库平均向量长度 0.631），角色质心几乎就是这个平均方向（余弦 0.978–0.997），而 O08 离平均方向最近（0.6895）→ 14/14 角色的语义 top1 全是 O08。这是 hub 效应，不是「白厄像赛飞儿」；归属只能看引用与兑现（详见 `f18` 与第 2 章方法小结）。
9. **事件级检索的失败是结论，不是 Bug**：把命中标准换成「真正的兑现段」后，v3 只剩 7 个可评问题、最好 MRR 0.132（六种方法全部接近失败）；失败原因是「短神谕句 × 长剧情步骤」的粒度错位，而不是某个方法调参不好。

## 两种表示与实验设计

| 表示 | 维度 | 看什么 | 主要短板 |
|---|---|---|---|
| 词频加权 TF-IDF | 11,737 | 词面重合、复述与引用 | 词袋丢语序；对改写/沉默无感 |
| LSA / SVD | 100 | 压缩后的主题方向 | 压缩会抹平稀有提示词 |
| BM25 | — | 长文档检索（带长度校正） | 仍是词面匹配 |
| SBERT `bge-small-zh-v1.5` | 512 | 语义相近、语域相近 | 有共同方向（hub 效应）、区分度低 |
| 检测器 A / B1 / B2 | — | 规则 + 特征打分（词面、情绪、语义突变、身份/位置、母题回收） | 只能给方向，不能替代人工 |

**检索实验（同一套 query 池、按 gold 与候选池分代）**：

| 版本 | gold（目标段） | 候选池 | 方法 | 可评问题 | 最好结果 |
|---|---|---|---|---|---|
| v1 | 吟诵步（角色把神谕念出来） | 686 | 5 种（关键词 / TF-IDF-char / TF-IDF-word / BM25 / LSA） | 13 | 关键词 MRR 0.731 |
| v2_mask | 同上（query 掩掉原句） | 686 | 5 种 | 13 | 关键词 MRR 0.660 |
| **v3** | **兑现事件段** | **661**（剔除 25 个含原句的吟诵步） | 6 种（+ SBERT） | **7** | **关键词 MRR 0.132** |
| v3_control | 兑现事件段 | 686 | 6 种 | 13 | 关键词 MRR 0.480 |

> v1 的高分主要来自「原句泄漏」（候选池里就有人在念原句）；v3 换掉 gold 后全面失败，这才是可以写进结论的部分。跨组 MRR 不能横比（可评问题数不同）。

## 如何运行

### 看报告页面

```bash
cd frontend
npm install
npm run dev          # 本地开发
# 或
npm run build && npm run preview
```

- 构建前会自动跑 `scripts/sync-assets.mjs`，把 `docs/report/figures/` 里的图拷进 `public/figures/`；
- 角色头像等素材在 `frontend/public/materials/`（本机生成，不入库；来源与脚本见 `tools/make_portraits.py` 与 `frontend/docs/07-素材清单.md`）；
- 页面结构：前言 → 第 0 章故事梗概 → 第 1 章从剧情到数据 → 第 2 章与命定交手 → 第 3 章改写命定 → 第 4 章对偶/长线/旁观者 → 第 5 章收束（三个专题 + 边界）。

### 复现分析

```bash
# 环境：conda env nlpLesson（Python 3.11 + torch CPU + sentence-transformers 6.x）
conda run -n nlpLesson python tools/export_artifacts.py        # 语料 → ids / 分词 / TF-IDF
conda run -n nlpLesson python tools/export_sbert.py            # 句向量缓存（Z_sbert_*.npy）
conda run -n nlpLesson python tools/export_character_centroids.py

conda run -n nlpLesson python tools/export_plot_data.py --all  # 新图 + 全部配对数据 + index
```


## 已知边界

- v3 只有 **7 个可评问题**，MRR 差别只能看方向；v1/v2/v3 不能横向比较。
- 74 步标注覆盖的是「人工认为重要的步骤」，不是全量 686 步；检测器只提供方向，不能当准确率。
- 语义相似度在「角色整体 × 神谕」这一层被 hub 效应支配（`f18`），只能用于同角色内部逐步比较。
- 角色曲是篇外文本（24 条歌词），只做探索性对照，不作为含义证明。
- 报告草稿（`AnalysisV2/draft/`）仍是草稿；`AnalysisV1/`（另一版）未合并进本仓库结论。
- 前端素材（头像、主视觉）与构建产物不入库，换机器需重新生成。

## 后续可能继续推进的方向

**本阶段（课程提交版）到此为止**；以下方向不代表承诺，只是如果后续继续做，会优先从这里开始：

1. **交互式检索 Demo**：输入一句台词/一条神谕 → 返回候选剧情段 + 引用阶段 + 兑现类型，把「NLP 帮人缩小阅读范围」这件事真正做出来；
2. **给语义表示去偏**：在 `f18` 的基础上做去均值 / all-but-the-top / whitening，再重跑事件级检索，看 v3 的 MRR 能不能从 0.132 抬起来；
3. **扩大语料**：支线、活动、角色曲、书籍文本是否也符合「共同体语言」的结论，需要语料外验证；
4. **标注扩量**：74 步 → 686 步全量（或主动学习挑点），让评测样本不只 7/13；
5. **逐句改写对齐**：把「神谕原句 ↔ 引用/改写句」做成句对，分类改动类型（换词 / 换语序 / 换主语 / 改变评价方向）；
6. **前端增强**：`record_id` 可点回原文、检索结果页、移动端排版；
7. **报告定稿**：把 `AnalysisV2/draft/` 合并稿打磨成长文/PDF 版本；
8. **工程化**：一条命令跑完的 pipeline + 数据/模型版本管理。
